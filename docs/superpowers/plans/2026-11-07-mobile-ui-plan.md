# 移动端 UI 适配实施计划

依据：`../specs/2026-11-07-mobile-ui-design.md`，完整设计已经用户确认。

本计划仅规划已确认范围，不代表代码已实施。当前允许技能没有 writing-plans，按正常代码分析流程编写；不调用其他未允许技能。

## 实施约束

- 原工作区 `Cloud115OfflineDialog.tsx` 及其测试的 200ms 刷新改动独立保留，不提交进移动端功能。
- 不修改后端协议、115 权限/账号边界、任务或编号算法，不新增移动 UI 框架。
- 每个阶段先补能复现目标行为的测试，再改实现；完成后运行前端全量测试及构建。不得将示意页代码直接当生产实现。
- 阶段内必要的布局重构可提交，但整个移动端功能在最终验收前不得声称完成。不自动推送、发布或更新 NAS。

## 1. 响应式视口与会话稳定性

涉及：`App.tsx`、`WorkspaceShell.tsx`、`FileWorkspace.tsx`、`WindowFrame.tsx`、`Cloud115Window.tsx`、`styles.css`、对应测试。

新增集中管理的响应式上下文（如 `useWorkspaceViewport`），用 `(max-width: 767px)` 判断移动展示，单独保存 pointer 能力。清理订阅；测试 767/768 边界与 resize。不得改写 `workspaceModeStorageKey`。

先测试并明确窗口内容的 React identity：保持稳定的窗口 ID、组件层级和 key，手机与桌面只切换壳层呈现，不能条件挂载两套内容。非活动窗口内容保留状态，但对交互与可访问性隐藏；避免两个活动视图同时处理键盘事件。

115 当前 location/history/selection 位于组件内部，必须保持挂载身份或将这些状态提取到窗口级会话容器；优先选择不重复订阅、不改变现有请求生命周期的最小改法。PowerRename、编辑器等同理。禁止为了移动端直接将整个 FileWorkspace 在两个不同组件间重建。

精简左右会话进入手机时映射为两个可切换会话，保持原绑定和保存偏好；回到宽屏恢复双栏。115 会话可以在手机打开，但不能被精简模式的可见窗口过滤误删。

验收：断点往返后本地路径、115 账号与历史、复选状态、滚动和文本草稿保留；后台任务不重复提交。解除全局和登录页 1024px 限制时只影响窄屏，不破坏桌面最小窗口规则。

## 2. 手机壳层、窗口切换与返回层级

新增 `MobileWorkspaceShell`、窗口切换列表与集中返回层控制（实际文件名可随实现调整）。消费共享会话/窗口元数据，不另建业务状态副本。

底部文件/窗口/任务入口和当前全屏工作页；无活动会话时显示本地根目录、115 入口。保留语言切换、版本与退出等已有入口，归入合适的更多菜单，不能因隐藏桌面任务栏而丢失。

统一注册最上层菜单、弹窗、工具和目录返回动作；浏览器 history 条目携带应用标记，不能拦截非本应用历史。保存确认可阻止关闭，确认通过后再消费返回动作，防止反复弹窗或循环 pushState。

新增端到端场景：窗口切换保持会话、关闭未保存文本需要确认、浏览器返回先关闭菜单再退出工具、正常退出应用不被锁住。

## 3. 共享文件列表的移动展示

涉及：`FilePane.tsx`、`FileRow.tsx`、`VirtualRootView.tsx`、`Cloud115Accounts.tsx`、`Cloud115Window.tsx`、导航与选择模块。

从现有行数据和文件图标构建手机列表，复用加载、选择 store、排序、刷新和路径解析。名称为主、元数据第二行；正常单击打开，多选模式点击只选中。根目录及 115 账号在手机上单击进入，桌面双击规则不变。

路径/根目录或账号切换、后退/上移/刷新和更多中的前进；排序入口包含原有字段。文件名过长换行或截断时必须可查看完整值。

手机列表禁用桌面文件拖动传感器，保证纵向 pan；不要同时禁用正常点击。测试手指移动不会打开或拖走文件，滚动后误触抑制有效。

验收：本地与 115 的行交互一致，未知文件类型不开启错误预览，大目录仍使用按需渲染，整个页面没有横向溢出。

## 4. 动作菜单、多选与剪贴板

涉及：`fileActions.ts`、`FileActionMenuItems`、`ActionToolbar`、`PaneContextMenu`、`appClipboard.ts`、`OperationPreview`。

共享动作模型渲染底部菜单；保留分隔、危险色、禁用状态和可读标签。当前目录菜单与单项菜单明确传递对象，不能为了单项菜单永久覆盖多选集合。

多选操作栏、全选和退出选择。复制/剪切复用应用剪贴板；切换目录后提供粘贴入口、来源摘要和取消，跨账号限制仍由既有逻辑执行。目标目录选择手机单击进入，桌面仍双击。

验收：本地→本地、本地↔115、115 同账号操作走原有预览；移动到本地仍显示删除源文件警告；115 不能调用本地连接点动作。所有远端写操作使用 mock 测试，不操作真实账号。

## 5. 表单、预览、详细信息与任务

涉及：`WindowDialogLayer`、共享 dialog/sheet、`SingleRenameDialog`、`ExtractDialog`、`OperationPreview`、`FileDetails`、媒体/文本预览、`JobsSheet`、`TransferProgress`。

短表单窄屏居中，长表单可滚动；大型编辑/预览全屏。统一安全区和底部灰色操作区，结合动态视口处理键盘，必要时观察 visualViewport 并正确清理监听。

任务在手机统一呈现列表与详情；不叠放多个 draggable 窗口。隐藏、切换或离开详情不调用取消，只有明确取消按钮发送请求。完成事件只能关闭对应任务页面，不能关闭用户随后打开的其他页面。

验收：文本未保存确认、115 只读文本、媒体直链逻辑不变；模态焦点可回到触发按钮；键盘弹出、长错误信息和安全区不遮挡确认按钮。

## 6. PowerRename 手机标签页

涉及：`RenameDialog.tsx` 中 `PowerRenameContent`、`powerRenameOptions.ts`、`cloud115Rename.ts`、对应测试。

控制器与预览状态不跟标签页卸载；规则和预览只切换可见内容。规则纵向排列，预览将原名/新名分成上下两行。保留全部选项、动态数量、禁用条件以及 115 属性读取限制。

新增测试：输入改变后旧预览失效，快速切换标签不重复执行，迟到响应不覆盖当前结果，切换窗口/断点不丢规则。仅看变化不改变真实执行集合。

## 7. SuperRename 手机目录审核

涉及：`SuperRenameContent.tsx`、`SuperRenameTree.tsx`、`superRenameManager.ts`、115 适配与对应测试。

用共享模型渲染目录组，组标题在独立滚动区域吸顶；右侧重命名按钮固定在标题布局内，长路径查看不依赖 title 悬停。子项显示完整目标相对路径，警告项与深层目录启用保留。

先验证当前 manager 的成功/失败和正在执行状态语义，再接界面。禁止以“提交成功”代替“任务完成”移除组；若共享状态不支持部分失败恢复，先补状态测试与最小修复，桌面语义也保持正确，不另造手机算法。

新增测试：取消勾选只重排本组；单组执行与批量执行不重复提交；失败组保留；成功组移除不跳回列表顶端；折叠不取消选择；启用深层目录不会重复处理父组项。

## 8. 全面验证与交付

组件验证命令：

```sh
cd web
npm test -- --run
VITE_APP_VERSION=0.4.0 npm run build
```

版本变量使用实施时当前正式版本，不在本功能中擅自升级。

增加 `web/e2e/mobile-workspace.spec.ts` 与批量工具移动场景；基于现有 Playwright 配置，先使用隔离测试服务及样例目录，再运行：

```sh
cd web
PLAYWRIGHT_BASE_URL=http://127.0.0.1:<测试端口> npx playwright test
```

端口以启动前检查结果为准，不覆盖用户既有服务。测试初始化、删除等用例运行前检查其数据路径，只能写专用测试目录。115 用请求拦截或 fake provider，不能向真实云端发测试写请求。

覆盖 360/390/430 宽度、横屏、桌面完整/精简模式；手机实际浏览器验证软键盘、滚动和返回。如果本环境只能模拟，必须在交付报告中区分已验证与等待真机验证项目，不能将模拟测试称为真机通过。

交付列明各功能提交、测试结果、剩余问题与临时测试服务地址。每次提交只暂存对应功能文件/代码块，尤其不纳入预先存在的离线刷新更改；完成用户要求之前不自动发布版本或部署 NAS。

## 风险检查与完成定义

- 保留挂载不等于后台重复加载：控制可见性与订阅职责，避免所有窗口都发重复刷新请求。
- 移动列表、桌面列表同时渲染会制造双份焦点与事件；每个会话只有一个活动展示。
- 响应式 CSS 不能全局取消桌面 minimum，也不能触屏滚动时触发拖动。
- 浏览器返回不能与文件历史互相重复导航；未保存确认与返回必须串行。
- 通过业务测试只是必要条件，布局、键盘、安全区和滚动仍需浏览器验证。

八个阶段全部完成且设计验收表逐项核对后，才可称为移动端适配完成。此计划不是新增产品设计，不需要重新选择此前已经确认的布局。
