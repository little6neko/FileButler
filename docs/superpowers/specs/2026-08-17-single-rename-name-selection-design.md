# 单文件重命名初始选区设计

## 目标

单文件重命名窗口打开时，按照 Windows 文件管理器的习惯预先选中文件名主体，便于用户直接输入新名称，同时避免意外覆盖扩展名。目录和没有扩展名的文件应全选。

## 选择规则

- 目录始终全选，即使目录名中包含点，例如 `photos.2026`。
- 普通文件只把最后一个点之后的内容视为扩展名。
- `photo.jpg` 选中 `photo`，保留 `.jpg`。
- `archive.tar.gz` 选中 `archive.tar`，保留 `.gz`；不维护复合扩展名列表。
- 没有点的文件名（例如 `README`）全选。
- 只有前导点的隐藏文件（例如 `.env`）全选。
- 有额外分隔点的隐藏文件（例如 `.env.local`）选中 `.env`，保留 `.local`。
- 点位于名称末尾时没有有效扩展名，因此全选。

## 前端设计

`DualPane` 已同时持有当前选中路径和对应的 `Entry`。打开单文件重命名窗口时，它把选中项的类型传给 `SingleRenameDialog`，使对话框能够区分文件与目录，而不是只根据名称猜测。

`SingleRenameDialog` 使用一个无副作用的选择范围计算函数：目录返回完整名称长度；文件查找最后一个点，只有该点既不是首字符也不是末字符时，才以该位置作为选择终点，其他情况均返回完整名称长度。

输入框保留现有自动聚焦行为，并只在第一次获得焦点时设置 `[0, selectionEnd)` 选区。首次选择完成后，组件重渲染或用户再次点击、聚焦输入框都不得重置选区。输入值、提交数据、键盘确认和后端重命名流程不作改变。

## 错误与兼容性

选区设置只使用标准文本输入框的 `setSelectionRange`，不会引入新的失败状态。若文件类型无法匹配到当前目录条目，按非目录文件处理；现有单选重命名流程正常情况下始终能够匹配该条目。

## 测试

组件测试覆盖以下行为：

- 单扩展名、多段文件名和无扩展名文件的初始选区。
- `.env` 与 `.env.local` 的隐藏文件边界。
- 带点目录仍然全选。
- 用户在首次选择后自行改变光标或选区，再次聚焦时不会被覆盖。
- 原有提交和空名称校验测试继续通过。

## 范围外事项

- 不识别 `.tar.gz` 等复合扩展名。
- 不修改 PowerRename 的搜索、替换或选区行为。
- 不修改任何后端接口或重命名规则。
