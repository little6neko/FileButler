# FileButler 网页桌面与多窗口文件管理设计

日期：2026-08-22  
状态：已批准

## 概述

FileButler 在保留现有双栏文件管理体验的同时，新增类似群晖 DSM 的网页版桌面。产品提供两种可随时切换的工作模式：

- **精简模式**：保留当前可调比例双栏文件管理器及“复制/移动到另一栏”等高效率操作。
- **完整模式**：显示桌面、统一顶部任务栏和任意数量的自由文件窗口。窗口可移动、八方向缩放、最小化、最大化、还原、关闭和切换层级；文件可在窗口之间拖放。

首版只把文件管理器做成桌面应用。任务中心、操作预览、重命名、批量重命名和媒体预览继续使用现有侧栏或对话框，但统一由页面级宿主管理。实现采用状态驱动的 React 窗口管理器，不引入第三方自由窗口框架。

## 目标

- 在单个浏览器页面中同时打开多个彼此独立的文件浏览窗口。
- 保留现有精简双栏模式，并使用任务栏按钮在两种模式之间转换。
- 两种模式共用顶部系统任务栏、文件会话、后台任务事件和应用内剪贴板。
- 支持跨窗口、跨根目录的文件拖放，并继续使用现有 dry-run 与操作确认流程。
- 支持应用内复制、剪切和粘贴快捷键及右键菜单。
- 通过清晰的状态边界避免窗口布局、文件浏览、拖放和后台任务逻辑重新耦合到一个大型组件中。
- 保持现有后端浏览、媒体和文件操作 API 兼容。

## 非目标

首版不包含：

- 窗口贴边吸附、半屏或四分屏、自动平铺、窗口分组和虚拟桌面。
- 刷新后的窗口、路径、选择或应用内剪贴板恢复。
- 手机、平板触控或小于 `1024px` 的视口适配。
- 文件图标网格视图；完整模式继续使用现有紧凑表格。
- 浏览器系统剪贴板、跨标签页粘贴或与操作系统文件管理器互拖。
- 除文件管理器之外的桌面应用窗口。
- 将任务中心、媒体预览或重命名界面改造成自由窗口。
- 键盘驱动的自由窗口移动或缩放。最大化、最小化、还原和关闭仍有可访问按钮。

## 术语

- **文件会话（Browser Session）**：一个独立浏览上下文，拥有位置、目录项、选择、排序、列宽、加载状态和错误状态。
- **虚拟根目录（Virtual Root）**：只存在于完整模式前端的“所有位置”页面，列出所有后端映射根目录；它不伪造后端 `rootId`。
- **活动窗口**：当前位于最前且未最小化的可见窗口；没有可见窗口时为空。
- **MRU**：按最近聚焦时间排列的窗口顺序，用于模式转换和关闭后的焦点回退。
- **可用桌面区域**：视口扣除固定顶部任务栏后的矩形区域。

## 现有约束

- 前端使用 React、TypeScript、Vite、shadcn/ui、Base UI 和 `dnd-kit`。
- 当前 `DualPane` 同时负责根目录加载、两栏状态、操作对话框、拖放、后台刷新和界面编排；它需要按职责拆分，而不是直接包进自由窗口。
- 当前 `FilePane` 的表格、排序、列宽、框选、选择存储、路径导航、目录拖放和上下文菜单应继续复用。
- 当前文件操作通过 dry-run、确认和后台任务执行；新交互不得绕过这些安全边界。
- 页面继续以桌面浏览器为目标，最小宽度保持 `1024px`。

## 架构

### 总体结构

```text
App / JobEventsProvider
└── WorkspaceShell
    ├── TopTaskbar
    ├── WorkspaceModeController
    ├── CompactWorkspace
    │   ├── left Browser Session → FileBrowserView
    │   └── right Browser Session → FileBrowserView
    ├── DesktopWorkspace / WindowManager
    │   └── WindowFrame[] → Browser Session → FileBrowserView
    ├── BrowserSessionRegistry
    ├── TransferCoordinator / AppClipboardStore / DndContext
    └── DialogHost / JobEventsStore
```

`WorkspaceShell` 在认证完成后始终存在。它加载根目录目录表、保存最后选择的模式、渲染统一顶部任务栏，并只显示当前模式的工作区。非活动模式的窗口和会话状态保留在内存中，以支持同一页面生命周期内的模式往返。

### WorkspaceShell

职责：

- 从 `localStorage` 读取和写入最后使用的模式。
- 首次使用默认进入完整模式；以后刷新进入上次使用的模式。
- 在完整模式启动时显示空桌面，不恢复上次窗口。
- 渲染固定顶部任务栏、任务中心入口、语言入口和版本。
- 持有页面级对话框宿主、传输协调器和键盘快捷键监听。
- 协调模式转换，不直接持有文件列表业务逻辑。

建议的模式类型为：

```ts
type WorkspaceMode = "compact" | "desktop";
```

### BrowserSessionRegistry

文件会话注册表是两种模式之间复用文件浏览状态的核心。窗口记录和双栏绑定只引用 `sessionId`，不复制文件业务状态。

```ts
type BrowserLocation =
  | { kind: "virtual-root" }
  | { kind: "directory"; rootId: string; path: string };

type BrowserSession = {
  id: string;
  location: BrowserLocation;
  entries: Entry[];
  loading: boolean;
  error: string | null;
  stale: boolean;
  selectionStore: FileSelectionStore;
  sortState: SortState;
  columnWidths: Record<ColumnKey, number>;
  requestGeneration: number;
};
```

注册表负责：

- 创建、读取、更新和释放文件会话。
- 加载真实目录；虚拟根目录直接读取 `RootCatalog` 渲染根目录卡片，不调用 browse API，也不把 `Root` 伪装成普通 `Entry`。虚拟根位置下 `entries` 保持为空。
- 在位置变化时清空不可见选择并更新可见顺序。
- 使用请求序号或 `AbortController` 阻止旧目录响应覆盖新位置。
- 按后台任务影响范围把匹配会话标为 `stale`：可见会话立即合并刷新，隐藏会话在下次变为可见时刷新，避免恢复出过期目录。
- 只在没有窗口或活动工作区继续引用时释放会话。

### FileBrowserView

`FileBrowserView` 从现有 `FilePane` 和 `DualPane` 中提取。它接收一个文件会话和呈现变体：

- `compact`：保留根目录选择器、当前路径、现有双栏操作语义和全局文件操作栏。
- `window`：隐藏根目录下拉选择器，提供“所有位置”入口、窗口内操作栏和完整模式上下文菜单。

它继续复用现有表格、选择、框选、排序、列调整、路径面包屑、媒体打开和目录拖放逻辑。文件窗口之间不会共享选择；同一个会话在模式转换时保留选择、排序和路径。

### DesktopWorkspace 与 WindowManager

窗口管理器只管理窗口几何和层级：

```ts
type WindowStatus = "normal" | "maximized" | "minimized";

type WindowRect = {
  x: number;
  y: number;
  width: number;
  height: number;
};

type FileWindowRecord = {
  id: string;
  sessionId: string;
  status: WindowStatus;
  statusBeforeMinimize: "normal" | "maximized" | null;
  rect: WindowRect;
  restoreRect: WindowRect;
  zOrder: number;
  lastFocusedAt: number;
};
```

`statusBeforeMinimize` 仅在 `status === "minimized"` 时非空，用来区分窗口应恢复为普通还是最大化；其他状态下必须为 `null`。

窗口状态通过 reducer 或等价的纯状态转换实现。创建、聚焦、移动、缩放、最小化、最大化、还原、关闭、视口重排和模式转换都有独立动作，可在不渲染 DOM 的情况下单测。

`WindowFrame` 负责标题栏、控制按钮、八个缩放手柄和指针捕获。它不请求目录、不解释文件拖放，也不打开业务对话框。

### TransferCoordinator

页面只保留一个 `DndContext`。现有固定的 `PaneKey = "left" | "right"` 泛化为稳定的浏览表面或会话 ID。协调器负责：

- 从来源会话解析有序选择。
- 在所有可见、未最小化窗口和精简栏中解析最上层有效目标。
- 处理目录行、当前目录、虚拟根目录卡片三类目标。
- 执行前端同目录、自身和后代目录校验。
- 构造现有 `OpsRequest` 并打开页面级 `OperationPreview`。
- 管理应用内剪贴板和粘贴目标。

### DialogHost 与后台任务

操作预览、新建目录、普通重命名、批量重命名、媒体预览和任务侧栏保持页面级。打开对话框时捕获来源会话、选择和目标位置，之后窗口焦点变化不能修改已经打开的操作。

现有 `JobEventsStore` 继续跟踪活动任务。由本页面创建的任务记录受影响 root/path；任务进入终态后把匹配会话标为过期，并立即刷新其中可见的会话。无法确定影响范围的外部任务使用保守回退：把全部真实目录会话标为过期并刷新当前可见会话。隐藏会话下次显示时刷新。多个终态事件合并为每会话一次刷新。

## 顶部任务栏与模式

### 任务栏布局

固定顶部任务栏高度为 `44px`，层级高于所有文件窗口。布局从左到右为：

1. FileButler 品牌标识。
2. 窗口按钮区域。
3. 自适应空白。
4. “完整 / 精简”模式切换按钮。
5. 活动任务入口。
6. 语言入口。
7. 版本信息。

现有 `AppShell` 左侧导航栏在两种模式中都移除。原“文件”和“任务”入口分别由当前工作区及顶部任务栏任务入口承接，避免顶部与左侧出现重复系统导航。

完整模式中，每个未关闭文件窗口有一个任务栏按钮，显示当前目录名；虚拟根目录窗口显示“文件管理器”。按钮最大宽度受限并省略长标题，按钮区域在空间不足时横向滚动，不自动合并窗口。

精简模式不产生自由窗口按钮，而显示一个固定的活动“文件管理器”工作区按钮。精简工作区不可最小化。

窗口按钮交互：

- 点击非活动的普通窗口：聚焦并置顶。
- 点击最小化窗口：恢复到最小化前状态并置顶。
- 点击当前活动窗口：最小化，并把活动状态交给 MRU 中下一个未最小化窗口；没有候选时清空活动窗口。
- 关闭活动窗口后：聚焦 MRU 中下一个未最小化窗口；若只剩最小化窗口则桌面无活动窗口。

### 模式持久化

只把最后选择的模式写入 `localStorage`。刷新后：

- 上次为完整模式：进入空桌面。
- 上次为精简模式：进入默认双栏，两栏都从第一个真实根目录的 `.` 开始。
- 根目录目录表为空：两种模式都显示“未配置映射根目录”的空状态。

窗口、文件路径、选择、排序和应用内剪贴板均不跨刷新恢复。

## 完整模式桌面

完整模式首次显示空桌面和一个“文件管理器”图标。每次双击该图标都创建新文件窗口，不复用或聚焦已有窗口。新窗口位置为虚拟根目录。

桌面图标不接受文件拖放。首版不提供壁纸选择、桌面文件、图标重排或桌面右键菜单。

### 虚拟根目录

虚拟根目录标题为“所有位置”，列出所有映射根目录。每个根目录卡片显示名称，并具有以下行为：

- 单击或按 Enter 进入该根目录的 `.`。
- 可作为文件拖放目标，目标为对应 `rootId` 的 `.`。
- 右键菜单在应用内剪贴板可用时提供“粘贴”。
- 不提供新建目录、重命名、批量重命名或删除虚拟根项目。

文件窗口位于虚拟根目录时，本窗口操作栏中的新建目录、重命名、批量重命名和删除全部禁用；进入真实根目录后按现有选择规则启用。

完整模式中，真实根目录的路径面包屑以“所有位置 / 根目录名”开始。在根目录顶层执行“返回上级”或点击“所有位置”会回到虚拟根目录。

精简模式不显示虚拟根目录，继续使用现有根目录选择器并把真实根目录顶层作为导航边界。

## 窗口行为

### 创建与层叠

窗口默认尺寸为可用桌面宽度的 `68%`、高度的 `72%`，同时满足：

- 最小尺寸 `560 × 360px`。
- 不超过可用桌面区域四周各 `12px` 的边界。

首个窗口从可用桌面左上角的 `(96, 40)` 开始；后续窗口每次向右 `28px`、向下 `24px`。如果下一个窗口会越过右侧或底部边界，则从起点重新循环。新窗口始终置顶。

不设置人为窗口数量上限。窗口创建逻辑不得依窗口数量注册新的页面级键盘、拖放或任务事件监听。

### 聚焦和层级

指针按下窗口内容、标题栏或控制按钮时，该窗口成为活动窗口并置顶。层级使用单调递增序号；在序号达到实现阈值时可按当前顺序重新归一化，不能改变视觉顺序。

文件拖放期间不因为经过一个窗口而自动置顶。只有指针可见命中的最上层窗口部分可以接收拖放。

### 移动和缩放

- 标题栏空白区域启动窗口移动；控制按钮和窗口内容不会启动移动。
- 八个边和角提供缩放命中区；缩放遵守最小尺寸和可用桌面边界。
- 移动和缩放使用 Pointer Events 与 pointer capture，并处理 `pointerup`、`pointercancel` 和组件卸载清理。
- 窗口不能完全移出桌面；至少完整标题栏保持在可用区域内。
- 视口尺寸变化时，最大化窗口重新匹配可用区域；普通窗口按相同边界规则收回可见区域并缩小到可容纳尺寸。

首版只支持指针移动和缩放，不实现吸附或触控专用手势。

### 最大化、最小化和关闭

- 标题栏最大化按钮或双击标题栏在最大化与还原之间切换。
- 最大化保存 `restoreRect`，填满可用桌面区域但不覆盖顶部任务栏。
- 最小化把当前普通或最大化状态写入 `statusBeforeMinimize`，再从桌面画布移除内容，但保留任务栏按钮。
- 从最小化恢复时回到最小化前的普通或最大化状态。
- 最小化活动窗口后按任务栏规则聚焦下一个可见 MRU 窗口；没有候选时桌面不保留活动窗口。
- 关闭移除窗口记录；对应文件会话在没有其他工作区引用后释放。

## 文件窗口内容与操作

每个窗口从上到下包含：

1. 标题栏和窗口控制。
2. 本窗口文件操作栏。
3. 位置导航与刷新。
4. 现有紧凑文件表格。
5. 本窗口状态栏。

窗口标题使用当前目录名；位于真实根目录顶层时使用根目录名；位于虚拟根目录时使用“文件管理器”。

每个窗口独立维护路径、选择、排序、列宽、加载和错误状态。窗口内工具栏保留新建目录、重命名、批量重命名和删除，不显示“复制到另一栏”或“移动到另一栏”。

目录双击继续在当前窗口导航。目录右键菜单新增“在新窗口中打开”，创建一个指向该目录的新会话和错位窗口。媒体文件继续在页面级媒体预览中打开。

## 应用内剪贴板

### 数据模型

```ts
type AppClipboard = {
  operation: "copy" | "move";
  sourceRootId: string;
  sourceParentPath: string;
  paths: string[];
  createdAt: number;
} | null;
```

剪贴板只存在当前标签页内，两种模式共享，不写入系统剪贴板或 `localStorage`。后一次复制或剪切覆盖前一次内容。

### 命令

- `Ctrl/Cmd+C`：把活动文件会话的有序选择保存为 Copy。
- `Ctrl/Cmd+X`：把活动文件会话的有序选择保存为 Move。
- `Ctrl/Cmd+V`：粘贴到活动窗口或活动精简栏的当前真实目录。
- 右键文件选择：提供“复制”和“剪切”。
- 右键真实目录行：可粘贴到该目录。
- 右键文件列表空白：可粘贴到当前目录。
- 右键虚拟根目录卡片：可粘贴到对应真实根目录的 `.`。

快捷键监听不得拦截 `input`、`textarea`、`select`、`contenteditable`、原生文本选择或打开对话框内部的复制粘贴。没有活动文件会话、没有选择、剪贴板为空或当前处于无具体目标的虚拟根页面时，快捷键不创建操作；应用显示本地化提示。

剪切来源仍可见时使用降低不透明度和剪切状态标记，但项目仍可选择和打开。切换模式不会清空剪贴板。

### 粘贴流程

1. 解析剪贴板和目标位置。
2. 运行与拖放相同的同目录、自身和后代目录前端校验。
3. 打开固定类型的 `OperationPreview`：Copy 剪贴板只预览 Copy，Move 剪贴板只预览 Move。
4. 使用现有 dry-run；冲突继续阻止确认。
5. 任务创建成功后，Move 剪贴板清空，Copy 剪贴板保留。
6. 解析、dry-run 或任务创建失败时剪贴板保持不变。

精简模式保留现有“复制/移动到另一栏”工具栏和右键命令，同时增加上述共享剪贴板命令。

## 跨窗口拖放

拖放来源包含 `sessionId`、真实 `rootId`、来源父路径和有序项目。可用目标为：

- 任一可见文件窗口或精简栏中的目录行。
- 任一可见文件窗口或精简栏的当前目录空白区域。
- 完整模式虚拟根目录中的根目录卡片。

最小化窗口、被上层窗口完全遮挡的区域、标题栏、任务栏和桌面图标不接受文件拖放。重叠可见区域按窗口层级过滤，只返回指针实际可见的最上层目标；目录行优先于当前目录空白目标。

拖放流程：

1. 拖动已选项目时保留并按当前可见顺序携带全部选择；拖动未选项目时把选择替换为该项目。
2. 解析目标。虚拟根目录卡片转换为对应 `rootId` 和 `.`。
3. 前端拒绝同目录、目录自身和目录后代目标。
4. 同根目录默认 Move，不同根目录默认 Copy。
5. 打开 `OperationPreview`，允许在 Move 和 Copy 之间切换，再执行 dry-run 和确认。
6. 任务创建成功后清理拖动状态和来源选择；任务终态后刷新受影响会话。

后端 planner 的递归目标和路径安全检查继续作为权威防线。

## 模式转换

### 完整模式到精简模式

1. 取当前活动窗口；若没有活动窗口，取 MRU 第一项。其文件会话绑定为左栏。MRU 候选包含最小化窗口，但不包含已关闭窗口。
2. 取 MRU 中下一个不同窗口的文件会话绑定为右栏，候选规则与左栏相同。
3. 任一选中会话位于虚拟根目录时，把该会话转换为第一个真实根目录的 `.`。切回完整模式时该会话仍停留在这个真实根目录，不恢复虚拟根位置。
4. 缺少窗口时，为缺少的栏创建位于第一个真实根目录 `.` 的文件会话。
5. 其他窗口记录和会话在内存中保留，但不渲染、不参与拖放或任务栏窗口列表。
6. 左栏成为活动栏；完整模式原活动窗口按第 1 步固定映射到左栏。

如果没有真实根目录，两栏显示无根目录空状态。

### 精简模式到完整模式

1. 左右栏文件会话分别绑定回对应文件窗口，保留在精简模式中产生的路径、选择和排序变化。
2. 已存在的对应窗口从最小化状态恢复为可见；普通矩形和最大化状态保留。
3. 没有既有窗口记录时，为左右栏创建两个按默认错位规则排列的普通窗口。
4. 先前暂存的额外窗口按原矩形、状态和相对层级恢复；原本最小化的额外窗口保持最小化。
5. 当前活动栏对应窗口置顶并成为活动窗口。

模式切换不清空应用内剪贴板，也不重复请求路径未变化且数据仍有效的会话。切换按钮在转换期间短暂禁用，避免重入。

## 错误处理与安全

- 每个文件会话在自身视图显示加载错误和重试入口；一个窗口失败不影响其他窗口。
- 根目录目录表加载失败时，顶部任务栏保持可操作；完整桌面和精简工作区都显示全局重试空状态。
- 旧目录响应由请求序号或取消机制丢弃。
- 无效窗口矩形在 reducer 边界归一化；Pointer Events 在取消、失焦和卸载时清理。
- 开始拖放、结束、取消、打开预览和卸载都会清理高亮与 overlay。
- 预览捕获不可变来源与目标；背后窗口焦点或路径变化不能修改已打开请求。
- dry-run 是目标存在、源缺失、权限、冲突和后端路径安全的权威结果。
- dry-run 或任务创建失败时预览保持打开，用户可重试或取消。
- 应用内剪贴板中的源路径过期时由 dry-run 报错，不静默修改或删除剪贴板。
- 模式转换使用单次 reducer 事务，不能短暂让同一文件会话同时作为可见窗口和精简栏参与拖放。

## 可访问性

- 顶部任务栏使用具名导航；每个窗口按钮暴露活动、最小化和窗口标题。
- 文件窗口是以标题栏为标签的独立 `region`，不是模态对话框，不捕获或循环 Tab 焦点。
- 最小化、最大化/还原和关闭使用明确的本地化按钮名称。
- 标题栏双击只是最大化按钮的指针快捷方式。
- 现有拖放屏幕阅读器播报泛化为窗口/会话名称，并说明来源数量、目标、默认操作、无效原因和取消。
- 文件工具栏、右键菜单和剪贴板快捷键提供拖放的非拖动替代路径。
- 有效和无效目标继续同时使用颜色、边框、文字和光标提示，不只依赖颜色。
- 动画遵守 `prefers-reduced-motion`；窗口移动和缩放本身不添加过渡延迟。

- 模式转换：0、1、2 和多个窗口；最小化窗口；虚拟根回退；额外窗口暂存与恢复；活动栏/窗口映射。
- 虚拟根目录：根目录项目合成、进入、面包屑返回、拖放和右键粘贴目标。
- 应用内剪贴板：Copy/Move 覆盖、路径顺序、编辑控件快捷键绕过、固定类型预览、成功清理和失败保留。
- 拖放：动态会话 ID、顶层可见目标、目录优先级、同目录和后代校验、跨根默认 Copy。

- 空桌面与文件管理器图标每次双击创建新窗口。

- 每个窗口独立的路径、选择、排序、列宽、工具栏和错误状态。

- 在 `1024×768`、`1440×900` 和 `1920×1080` 下打开、移动、缩放、最大化、最小化、恢复和关闭三个窗口。

- 保持现有选择、框选、表格排序、列缩放、双击导航、媒体预览、重命名、批量重命名、任务刷新和拖放场景通过。
- 最终验证运行 Go 测试、前端测试、lint、类型检查生产构建和重点 Playwright 场景。

## 验收标准

- 用户可在完整模式空桌面上连续双击文件管理器图标，并得到多个独立、错位层叠的虚拟根窗口。
- 每个窗口可移动、八方向缩放、最大化、还原、最小化和关闭，且不能丢失到可用桌面之外。
- 顶部任务栏为每个完整模式窗口显示独立按钮，并可准确聚焦、最小化和恢复窗口。
- 虚拟根目录显示全部映射根目录，支持进入、拖放和右键粘贴。
- 文件可在任意可见窗口之间拖放；有效拖放始终进入可切换 Copy/Move 的现有安全预览。
- `Ctrl/Cmd+C/X/V` 和右键复制、剪切、粘贴在两种模式中共享同一应用内剪贴板，并遵守确认和清理规则。
- 完整模式窗口与精简模式双栏按活动/MRU 规则转换；额外窗口在切回完整模式后恢复。
- 精简模式保留当前双栏核心行为、直接跨栏操作和可调分隔条，同时使用新的统一顶部任务栏。
- 刷新只保留最后使用的模式，不恢复窗口或剪贴板。
- 所有现有后端 API 和安全校验继续生效，现有回归测试与新增测试通过。
