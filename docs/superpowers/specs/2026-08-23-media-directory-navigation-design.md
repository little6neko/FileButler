# 媒体目录切换设计

## 目标

为完整模式媒体应用窗口和精简模式媒体预览弹窗增加左右切换按钮，使用户能够按照打开预览时文件列表的当前排序，在同一目录的图片和视频之间切换。切换列表不递归包含子目录。

## 已确认交互

- 采用悬浮圆形左右按钮，位于媒体内容区左右中部。
- 鼠标移出整个媒体窗口或精简模式预览弹窗后，按钮渐隐至完全消失。
- 鼠标进入窗口或弹窗后，按钮以半透明状态渐显。
- 鼠标移到可点击按钮上时，按钮渐变为完全显现并增强背景反馈。
- 到达首个或末个媒体时，对应方向按钮变灰且不可点击；禁用按钮悬停时不增强。
- 按钮出现、消失和悬停状态变化都使用短时渐变动画。
- 完整模式和精简模式使用相同的列表、首尾和按钮交互；精简模式仍保持页面级弹窗，不加入任务栏。
- 本次只增加鼠标按钮，不增加键盘左右方向键、媒体计数器、缩略图条或自动播放。

## 目录快照与排序

打开媒体时，从发起预览的文件会话捕获目录快照。快照由当前目录直接条目构成，因此天然不包含子目录中的文件。构建过程：

1. 读取文件会话选择存储中的可见路径顺序；该顺序已经反映文件列表当前的名称、类型、大小或修改时间排序。
2. 按可见顺序映射当前会话的条目。
3. 排除目录和扩展名不受支持的普通文件，只保留 `mediaKindForPath` 可识别的图片与视频。
4. 找到本次双击媒体在过滤列表中的索引，并保存根目录 ID、媒体条目数组和当前索引。

如果可见顺序尚未初始化，则回退到会话条目的现有顺序，并保证本次打开的媒体进入快照。文件名相同但相对路径不同的条目仍按完整相对路径区分。

快照在预览关闭前保持不变。来源文件窗口关闭、导航、刷新或重新排序不会修改已打开预览的列表；目录中新建、删除或重命名媒体也不会动态加入或移出当前快照。重新打开预览时才读取最新目录状态。

## 状态模型

新增独立纯状态模块管理媒体画廊快照：

- `MediaGalleryItem`：文件名、相对路径和媒体种类；
- `MediaGallerySnapshot`：根目录 ID、按显示顺序排列的条目和当前索引；
- 快照构造函数：根据目录条目、可见路径顺序和当前路径生成有效快照；
- 相邻切换函数：在索引范围内返回新快照，越界时保持原状态；
- 当前条目读取函数以及上一项、下一项可用性判断。

纯状态模块不依赖 React、窗口管理器或 API，便于单独验证排序、过滤、首尾和不可变更新。

完整模式的 `MediaPreviewInstance` 保存实例 ID 和画廊快照。精简模式的页面级 `mediaPreview` 直接保存画廊快照。媒体 URL 继续通过当前条目的根目录 ID 和相对路径由 `api.mediaUrl` 构造，不新增网络请求或后端状态。

## 打开、复用与切换

`FilePane` 仍把被双击的媒体条目交给 `FileWorkspace`，但回调同时携带来源会话身份，以便从该会话捕获可见排序和目录条目。

完整模式打开媒体时：

1. 先检查是否已有媒体窗口的当前条目与本次根目录 ID、相对路径一致。
2. 若存在，则恢复并聚焦该窗口，不替换它已有的快照。
3. 若不存在，则创建新的媒体快照、实例和应用窗口。

左右按钮只更新当前预览实例的索引，不创建新窗口。切换后，媒体内容、窗口标题、标题栏图标、任务栏标题和任务栏媒体图标都读取新当前条目并同步更新。

精简模式左右按钮更新页面级快照索引，弹窗保持打开并更新标题和内容。

多个独立窗口可持有各自快照。若不同窗口通过左右按钮切换到同一个媒体，允许它们继续独立显示该文件；不跨窗口抢焦点、不关闭当前窗口。之后从文件列表直接双击该媒体时，聚焦其中当前显示该路径的最近活动窗口。

## 组件与视觉结构

`MediaPreviewContent` 增加以下输入：

- 上一项和下一项是否可用；
- 上一项和下一项回调；
- 本地化的上一媒体、下一媒体可访问名称。

组件在媒体元素两侧渲染原生按钮和 Chevron 图标。按钮使用绝对定位，不改变媒体可用尺寸。按钮层位于图片或视频上方，但避开视频底部原生控制区域。

切换时为当前媒体元素设置基于相对路径的 React `key`，确保旧视频卸载并停止播放，新图片或视频重新挂载。视频仍不自动播放。

完整模式通过媒体 `WindowFrame` 的悬停状态控制按钮整体显隐；精简模式通过带专用类名的 `DialogContent` 控制。基础状态透明且不接收指针事件，父容器悬停后按钮变为半透明并恢复指针事件，可用按钮自身悬停后变为完全不透明。禁用按钮保持灰色、禁用鼠标事件和较低不透明度。

动画只过渡透明度、背景色、颜色和轻微阴影，时长约 180 毫秒，不改变位置和尺寸，避免媒体画面抖动。焦点可见状态保持清晰，按钮具有本地化 `aria-label`。

## 首尾与异常行为

- 当前为首项时，上一按钮显示为灰色并禁用。
- 当前为末项时，下一按钮显示为灰色并禁用。
- 目录快照只有一个媒体时，两个按钮都显示为灰色并禁用。
- 越界切换不会改变索引、URL、标题或媒体播放状态。
- 快照中的文件在打开后被删除、移动或重命名时，当前媒体沿用浏览器现有加载失败行为；左右按钮仍可切换到快照中的其他条目。
- 图片或视频加载失败不关闭预览，也不自动跳过该条目。
- 切换媒体不会重新读取目录，不会修改来源文件窗口的选择或路径。

## 测试素材

在当前测试服务的“测试目录 A”根目录增加多张可区分的 PNG 测试图片，覆盖横向、纵向、方形和超宽宽高比。测试文件只用于运行中的测试目录，不写入项目源码或 Git 历史。

现有图片和视频继续保留，以便验证混合媒体切换、视频停止播放以及任务栏标题和图标从图片切换为视频。

## 自动化与实际验证

自动化测试覆盖：

- 快照严格遵循当前可见排序，只包含当前目录可预览媒体；
- 默认顺序回退、当前条目定位和非媒体过滤；
- 上一项、下一项不可变切换及首尾越界保护；
- 完整模式打开窗口、切换内容、标题和任务栏图标；
- 同一媒体直接打开时复用已有窗口，不同窗口的方向切换互不干扰；
- 来源文件窗口关闭和模式往返后快照仍可使用；
- 精简模式弹窗支持相同切换并在模式切换时继续按现有逻辑关闭；
- 单媒体时两个按钮禁用，首尾分别禁用对应按钮；
- 按钮可访问名称、禁用属性和媒体元素重新挂载；
- CSS 显隐、悬停、禁用和约 180 毫秒渐变规则存在。

实现完成后运行前端完整测试、生产构建和 Go 测试，并在真实 Chrome 中使用新增图片与现有 MP4 验证鼠标进入、移出、按钮悬停、首尾禁用、不同宽高比、完整/精简模式和混合媒体切换。

## 验收标准

- 两种模式都能按打开时文件列表当前排序切换同目录图片和视频，不包含子目录。
- 左右按钮的位置、半透明、完全显现、渐隐动画和灰色禁用状态符合已选择的 A 方案。
- 切换同步更新完整模式窗口标题、图标和任务栏信息，视频不会继续在后台播放。
- 目录变化和来源窗口生命周期不改变已打开快照。
- 不新增后端请求、持久化状态、键盘切换或额外浏览控件。
- 多种宽高比测试图片可在 8082 测试服务中直接使用，自动化测试、构建和实际浏览器验证通过。
