# 媒体预览应用窗口设计

## 目标

在完整模式中把页面级媒体预览弹窗改为独立应用窗口，使图片和视频预览能够与文件管理器、PowerRename 一样移动、缩放、最大化、最小化、关闭，并在任务栏中拥有独立按钮。精简模式继续使用当前页面级预览弹窗。

## 范围

本次改动只调整前端媒体预览的状态归属、窗口集成和布局。后端媒体读取接口、支持的媒体类型、文件列表打开手势和视频播放策略保持不变。

支持以下行为：

- 完整模式可以同时打开多个不同媒体文件的预览窗口。
- 同一个 `rootId + relativePath` 再次打开时，不创建重复窗口，而是恢复并聚焦已有窗口。
- 每个媒体窗口具有移动、八方向缩放、最大化、还原、最小化和关闭能力。
- 每个媒体窗口在任务栏中具有独立按钮，标题显示文件名并使用媒体图标。
- 图片和视频在可用内容区内保持宽高比自适应；视频保留浏览器原生控件且不自动播放。
- 媒体窗口独立于来源文件窗口。来源窗口导航、最小化或关闭不影响已经打开的预览。
- 切换到精简模式时，完整模式媒体窗口保留在窗口管理状态中但不显示；返回完整模式后恢复原来的窗口状态。
- 精简模式继续一次显示一个页面级媒体预览弹窗；切换模式时该弹窗按照现有瞬态界面清理逻辑关闭。

不包含以下内容：

- 新增音频、PDF 或其他文件类型的预览。
- 媒体编辑、幻灯片、播放列表、缩放工具栏或图片旋转。
- 自动播放视频或保存视频播放进度。
- 将精简模式改造成多窗口工作区。
- 修改媒体 URL 或后端流式传输逻辑。

## 方案选择

采用扩展现有窗口管理器的方案。新增媒体预览窗口记录和对应实例状态，并继续由 `WindowFrame` 渲染窗口框架。这能复用现有的边界限制、层级、聚焦、任务栏、移动和缩放行为。

未采用给现有 `Dialog` 单独增加拖动逻辑的方案，因为它会重复窗口手势和边界处理，且无法自然满足任务栏、最小化和多实例要求。也不把预览放入来源文件窗口的子弹窗层，因为媒体预览需要独立生命周期。

## 状态与窗口模型

`windowManager` 新增 `MediaPreviewWindowRecord`，窗口种类为 `mediaPreview`，通过 `instanceId` 指向页面持有的媒体实例。`DesktopWindowRecord` 扩展为文件窗口、PowerRename 窗口和媒体预览窗口的联合类型。

媒体实例保存：

- 实例 ID；
- 根目录 ID；
- 相对路径；
- 文件名；
- 媒体 URL；
- 媒体种类（图片或视频）。

`FileWorkspace` 使用实例映射管理这些快照。打开媒体时，以 `rootId + relativePath` 查找已有实例及其窗口：

1. 若窗口已经可见，则提升层级并聚焦。
2. 若窗口已最小化，则恢复原来的普通或最大化状态并聚焦。
3. 若不存在，则创建实例和窗口，使用窗口管理器的级联初始位置。

关闭媒体窗口时先从窗口管理器删除窗口，再删除对应媒体实例。媒体实例不写入本地存储或后端；刷新页面后不恢复。

媒体窗口使用适合预览内容的最小尺寸，但仍由现有桌面边界约束负责在小视口下降级。初始尺寸继续采用统一的级联窗口比例，避免引入媒体元数据加载前后的窗口跳动。

## 组件结构

`MediaPreview` 拆分为两层：

- `MediaPreviewContent` 只负责渲染响应式图片或带原生控件的视频，可被不同容器复用。
- `MediaPreview` 继续使用现有 `Dialog` 包装内容，供精简模式使用。

完整模式在 `renderDesktopWindow` 中识别媒体窗口，通过 `WindowFrame` 渲染 `MediaPreviewContent`。窗口标题使用文件名；内容区使用深色或中性色背景居中媒体，媒体元素限制在内容区宽高内并保持比例。窗口尺寸变化只触发布局重排，不重新创建 URL 或媒体实例。

`WorkspaceShell` 的任务栏窗口类型扩展为媒体预览，并显示对应媒体图标。任务栏点击沿用已有规则：点击非活动或最小化窗口会聚焦或恢复；再次点击当前活动窗口会最小化。任务运行侧栏也继续在选择任务栏窗口时关闭。

## 模式切换

完整模式媒体窗口属于持久的内存窗口状态，与文件窗口和 PowerRename 窗口一致。模式切换不会删除这些窗口或实例，只会由工作区模式决定是否渲染窗口和任务栏按钮。

精简模式打开媒体时仍写入当前页面级 `mediaPreview` 状态。`dismissTransientUIForModeChange` 继续清空该状态，因此精简模式弹窗不会泄漏到完整模式。完整模式不再写入该页面级状态。

## 错误与边界行为

- 媒体文件在窗口打开后被移动、重命名或删除时，浏览器按照现有媒体元素加载失败行为处理；本次不增加后端探测请求。
- 文件名相同但根目录或相对路径不同的媒体视为不同文件，可分别打开。
- 同一路径的图片和视频类型由扩展名判定逻辑决定，窗口复用键不依赖显示名称。
- 来源文件窗口关闭后，媒体实例中的 URL 和身份快照保持不变。
- 关闭窗口后再次打开同一文件会创建全新实例和窗口。
- 浏览器刷新会清空所有媒体窗口，符合当前桌面窗口的非持久化行为。

## 测试

前端单元与集成测试覆盖：

- 窗口管理器可创建、识别和约束媒体预览窗口，并应用媒体窗口最小尺寸。
- `MediaPreviewContent` 正确渲染图片和视频，精简模式 `MediaPreview` 仍保留可访问的命名对话框。
- 完整模式双击图片或视频后创建媒体应用窗口和对应任务栏按钮。
- 打开不同媒体产生多个窗口；再次打开同一媒体只恢复并聚焦已有窗口。
- 任务栏、最小化、最大化、缩放、移动和关闭沿用统一窗口行为，关闭后实例被清理。
- 来源文件窗口关闭或导航不会关闭媒体窗口。
- 精简模式仍打开页面级弹窗，切换模式时弹窗关闭；完整模式媒体窗口在模式往返后恢复。
- 现有文件窗口、PowerRename、任务栏和媒体弹窗测试继续通过。

实现完成后运行前端完整测试和生产构建，并在当前测试服务中用 `媒体预览测试图片.png` 与 `媒体预览测试视频.mp4` 实际验证打开、移动、缩放、最大化、最小化、任务栏恢复和同文件复用。

## 验收标准

- 完整模式中的图片和视频以独立窗口打开，而不是页面级 Dialog。
- 媒体窗口可移动、缩放、最大化、最小化、关闭，并有独立任务栏按钮。
- 不同媒体可并行预览；同一媒体不会创建重复窗口。
- 媒体始终保持比例并限制在窗口内容区内，视频不自动播放。
- 精简模式媒体弹窗和模式切换清理行为保持正确。
- 不引入后端接口或持久化改动，相关自动化测试与构建通过。
