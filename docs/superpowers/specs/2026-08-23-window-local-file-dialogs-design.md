# 完整模式文件窗口内子弹窗设计

日期：2026-08-23

状态：已批准

## 概述

完整模式中的新建文件夹、普通重命名以及文件操作预览从页面级单例弹窗改为所属文件窗口内的局部子弹窗。子弹窗只遮挡父文件窗口的内容区，随父窗口移动和缩放并始终居中；不同文件窗口可同时拥有各自的子弹窗，但同一文件窗口同一时间最多一个。

复制和移动确认归属目标窗口：键盘或右键粘贴在哪个窗口执行，或者文件拖放到哪个窗口，预览就显示在哪个窗口。删除确认归属发起删除的文件窗口。子弹窗不是桌面应用窗口，不创建窗口管理记录，也不显示任务栏按钮。

精简模式保留现有页面级弹窗行为，后台任务 API、任务 ID、SSE 进度和内存任务存储不变。

## 目标

- 在完整模式中让新建文件夹、普通重命名、复制、移动和删除确认成为文件窗口内的局部弹窗。
- 允许不同文件窗口同时打开各自的普通重命名或其他子弹窗。
- 保持标题栏、窗口移动、八方向缩放、最大化、最小化和关闭能力可用。
- 把弹窗尺寸限制在父文件窗口内容区内，防止长路径撑破窗口。
- 让文件操作预览同时支持垂直和水平滚动，长路径保持可查看。
- 隔离各窗口的弹窗、焦点、快捷键和异步响应，避免互相关闭或全局阻塞。
- 复用完整模式与精简模式的表单和预览业务逻辑。

## 非目标

本次不包含：

- 把 PowerRename、媒体预览、任务侧栏或认证弹窗改成局部子弹窗。
- 给子弹窗增加任务栏按钮、自由拖动能力或独立窗口几何记录。
- 允许同一个文件窗口叠加多个子弹窗。
- 刷新页面后恢复子弹窗或未提交输入。
- 修改文件操作、普通重命名、任务执行或 SSE 的后端协议。
- 改变精简模式现有页面级弹窗的布局和归属。

## 已确认的产品行为

### 弹窗归属与并发

- 每个文件窗口同一时间最多一个子弹窗。
- 不同文件窗口的子弹窗彼此独立，可以同时显示和操作。
- 新建文件夹、普通重命名和删除归属命令来源文件窗口。
- Ctrl/Cmd+V、右键粘贴和虚拟根目录中的根卡片粘贴归属接收粘贴的目标文件窗口。
- 跨窗口拖放归属鼠标释放时的目标文件窗口。
- 切换焦点到其他文件窗口不会关闭原窗口的子弹窗。
- 子弹窗不加入桌面窗口管理器和任务栏。

### 父窗口交互与生命周期

局部遮罩只覆盖标题栏下方的文件内容区。标题栏和缩放边缘保持可操作，因此用户可以在子弹窗存在时移动、缩放或最大化父窗口。弹窗是父窗口 DOM 的一部分，父窗口几何变化后由布局自动重新约束并居中。

- 移动、缩放或最大化父窗口：保留子弹窗及其当前状态。
- 聚焦其他桌面窗口：保留子弹窗。
- 最小化父窗口：关闭并丢弃该窗口的子弹窗。
- 点击活动任务栏按钮导致父窗口最小化：执行相同清理。
- 关闭父窗口：同时关闭并丢弃其子弹窗。
- 完整模式切换到精简模式：关闭并丢弃全部完整模式子弹窗。
- 切回完整模式：不恢复先前被清理的子弹窗。
- 按 Escape 或点击窗口内容区内的局部遮罩：只关闭当前子弹窗。

若用户已经点击提交，最小化、关闭父窗口、切换模式、Escape 或遮罩关闭只移除界面，不尝试取消已经发出的请求。服务端成功接受请求后仍注册任务；失败时若原弹窗已消失，则使用全局错误提示。

## 状态与数据模型

### 按父窗口保存的子弹窗注册表

`FileWorkspace` 增加按 `windowId` 索引的局部弹窗注册表。每条记录带唯一 `dialogId` 和打开时的稳定快照：

```ts
type WindowDialogState =
  | {
      dialogId: string;
      kind: "mkdir";
      windowId: string;
      rootId: string;
      directoryPath: string;
    }
  | {
      dialogId: string;
      kind: "singleRename";
      windowId: string;
      rootId: string;
      path: string;
      initialName: string;
      entryType: Entry["type"];
    }
  | {
      dialogId: string;
      kind: "operation";
      windowId: string;
      request: OpsRequest;
      operationChoices?: readonly DragOperation[];
      clearMoveClipboard?: boolean;
    };

type WindowDialogs = Partial<Record<string, WindowDialogState>>;
```

记录以 `windowId` 为键，自然保证每个父窗口最多一个子弹窗。统一的打开转换在目标窗口已有记录时不执行替换，避免程序化重复触发丢弃当前输入。`dialogId` 用于异步响应身份校验：旧弹窗关闭后，即使同一父窗口又打开了新弹窗，旧请求也不能关闭或写入新弹窗。

新建文件夹保存打开时的根目录与当前目录；普通重命名保存根目录、相对路径、初始名称和条目类型；文件操作保存完整请求和操作模式选项。弹窗不在后续渲染中重新读取当前选择来决定目标，避免目录刷新、选择变化或其他任务影响已打开操作。

### 完整模式与精简模式边界

完整模式的操作回调同时携带 `windowId` 和 `sessionId`，并写入 `WindowDialogs`。精简模式继续写入现有页面级 `mkdirSessionId`、`singleRenameSessionId` 和 `previewState`，不创建局部弹窗记录。

模式切换到精简模式前统一清空 `WindowDialogs`。桌面窗口、浏览会话和 PowerRename 应用实例仍按现有规则保留。

## 组件设计

### 可复用弹窗内容

现有 `MkdirDialog`、`SingleRenameDialog` 和 `OperationPreview` 拆分为业务内容与容器两层：

- 内容层负责输入、预览、冲突、错误、提交状态、Enter 确认和按钮。
- 页面级包装继续使用 Base UI `Dialog`，供精简模式使用。
- 完整模式包装使用新的窗口内子弹窗层。

两种容器共用相同内容层和提交回调，避免完整模式与精简模式出现不同验证或请求行为。局部子弹窗不复用 Base UI 的页面级模态 Portal，因为其全局遮罩、全局焦点管理和固定视口定位会阻止多个文件窗口独立工作。

### WindowFrame 局部弹窗层

`WindowFrame` 接收可选的局部弹窗节点，在 `.desktop-window-content` 上方渲染一个只覆盖内容区的绝对定位层。标题栏不在遮罩范围内，窗口缩放手柄的层级高于局部遮罩。

局部层包含：

- 只拦截父窗口内容区指针事件的半透明遮罩；
- 使用 `role="dialog"`、标题关联和初始焦点的可访问弹窗面板；由于其他桌面窗口仍可操作，不声明页面级 `aria-modal="true"`；
- 在父内容区内使用居中布局的尺寸约束容器；
- 只在当前弹窗内部处理 Escape、Enter 和 Tab 循环的键盘边界。

局部弹窗不会创建 `DesktopWindowRecord`，因此不会改变任务栏、MRU 窗口顺序或窗口管理器的最小尺寸逻辑。打开弹窗时聚焦其父窗口；之后点击其他窗口仍允许焦点离开局部弹窗。

## 操作数据流

### 工具栏和右键操作

文件窗口渲染操作栏与上下文菜单时，把所属 `window.id` 传入命令构造器：

1. 新建文件夹捕获当前目录位置并创建 `mkdir` 记录。
2. 普通重命名捕获当前单选条目并创建 `singleRename` 记录。
3. 删除捕获当前有序选择并创建 `operation` 记录。
4. 内容区立即被局部遮罩阻塞，因而同一窗口无法继续触发第二个操作；其他窗口仍可触发自己的操作。

### 粘贴和拖放

键盘粘贴使用当前活动文件窗口 ID。右键粘贴由菜单创建时携带父窗口 ID。虚拟根目录中的根卡片同样携带所属文件窗口 ID。

`FileDropData` 增加可选目标文件窗口 ID；完整模式的 `FilePane` 和 `VirtualRootView` 写入该字段，精简模式保持无窗口归属。拖放结束时根据目标数据决定：

- 完整模式且存在目标窗口 ID：在目标窗口创建局部复制/移动预览；
- 精简模式：继续打开页面级操作预览。

已有局部子弹窗的文件窗口必须禁用其内容区和根卡片的 droppable 注册，碰撞检测也忽略该窗口的底层目标。这样从其他窗口拖入文件时不会穿透局部遮罩并替换现有弹窗。

默认移动/复制判断、目标有效性检查和 `OpsRequest` 构造继续使用现有纯函数。

## 提交、错误与异步一致性

每次关闭局部弹窗都按 `windowId + dialogId` 条件删除，异步回调也使用相同身份检查。

- 创建任务成功：若原记录仍存在则关闭它；无论界面是否仍存在，都调用现有任务注册流程。
- 创建任务失败：若原记录仍存在则在当前弹窗内显示并允许重试；若已不存在则显示全局错误提示。
- 剪切粘贴：只有移动任务创建成功后才清空应用剪切板。
- 操作预览失败或冲突：只影响当前子弹窗，保持现有错误和禁用确认行为。
- 子弹窗被关闭或替换后，旧预览响应不得更新新实例。
- 多个文件窗口的预览状态、操作模式和错误完全隔离。

普通重命名和新建文件夹在提交过程中继续使用当前忙碌状态防止重复点击。界面被清理后不发送取消请求，因为 POST 可能已经到达服务端；其最终结果仍按上述规则处理。

## 焦点与快捷键

局部弹窗不设置页面级 inert，也不使用会把焦点强行拉回的全局焦点锁。打开时聚焦输入框或预览内容；在该弹窗接收键盘事件时，Tab 在其可聚焦元素间循环。用户通过鼠标或任务栏激活另一窗口时允许焦点离开。

当前基于 `document.querySelector("[role='dialog']")` 的全局文件快捷键阻止逻辑改为作用域判断：

- 页面级弹窗或媒体预览存在时继续阻止文件快捷键；
- 当前活动文件窗口拥有局部子弹窗时阻止该窗口的复制、剪切和粘贴；
- 只有非活动文件窗口拥有局部子弹窗时，不阻止当前活动窗口的文件快捷键；
- 编辑输入框中的原生复制、剪切和粘贴保持不变。

## 尺寸、居中与滚动

局部层占满父窗口内容区并使用网格居中。面板宽高使用父容器百分比和固定内边距共同约束；父窗口移动时面板随 DOM 一起移动，父窗口缩放或最大化时 CSS 自动重新计算可用尺寸和中心位置。

- 面板不得超出父内容区，并至少保留一圈小间距。
- 简单输入弹窗保留现有合理最大宽度，但在窄窗口中收缩到可用宽度。
- 输入框设置 `min-width: 0`，超长名称由输入控件自身水平滚动。
- 操作预览面板采用标题、可滚动主体和固定底部操作区的纵向布局。
- 预览主体设置 `min-width: 0`、`min-height: 0` 和 `overflow: auto`。
- 路径单元格保持单行，表格保留内容所需的内在最小宽度；过长内容只扩展内部滚动面，不扩展外层面板。
- 浏览器水平滚动条、Shift+滚轮及触控横向滑动均由原生 overflow 行为提供。
- 父窗口高度较小时，主体同时承担垂直滚动，标题和确认按钮保持可见。

## 测试与验收

### 组件与状态测试

- 两个文件窗口可同时显示各自的普通重命名弹窗。
- 同一文件窗口只有一个局部弹窗记录，重复打开请求不会替换现有记录。
- 新建文件夹、普通重命名和删除归属来源窗口。
- 键盘粘贴、右键粘贴、根卡片粘贴和跨窗口拖放归属目标窗口。
- 子弹窗不增加任务栏按钮，也不阻止其他窗口交互。
- 拖放碰撞不会穿透局部遮罩命中该窗口的底层目录。
- 聚焦其他窗口保留原弹窗；最小化、关闭父窗口或切换精简模式清除它。
- 移动、缩放和最大化不清除弹窗。
- 当前活动窗口的局部弹窗阻止文件快捷键，非活动窗口的弹窗不全局阻止快捷键。
- 提交完成后仅关闭匹配 `dialogId` 的记录；旧响应不影响后来打开的新弹窗。
- 已清理弹窗的任务成功仍被注册，失败使用全局提示。
- 移动剪切板只在任务创建成功后清空。
- 精简模式继续使用页面级弹窗并保持既有行为。

### 弹窗内容回归测试

- 新建文件夹和普通重命名保持输入验证、初始选择、Enter 确认、忙碌状态和错误处理。
- 复制、移动和删除预览保持 dry-run、模式切换、冲突禁用、Enter 确认及任务创建行为。
- 多个预览实例的请求和错误互不影响。
- 操作预览滚动主体具有水平与垂直 overflow，长路径不会扩张外层面板。

### 浏览器验收

- 遮罩只覆盖内容区，标题栏拖动、最大化、最小化、关闭和八方向缩放可用。
- 父窗口移动、缩放和最大化后，面板始终在当前内容区中央。
- 小尺寸父窗口中面板不越界。
- 超长来源和目标目录可通过水平滚动条或触控横向滑动完整查看。
- 多个窗口的局部弹窗可以同时显示并分别关闭或提交。

### 完整回归

- 运行前端全部单元测试、lint 和生产构建。
- 运行 Go 全量测试，确认前端重构未改变任务创建、执行和 SSE 行为。
- 在当前测试服务中实测完整/精简模式切换、跨窗口拖放、剪切粘贴及任务侧栏刷新。

## 实施边界

实现优先复用现有 `WindowFrame`、文件操作请求构造、弹窗内容、任务注册和窗口管理纯函数。新增代码集中在局部弹窗状态、局部容器、模式分派和目标窗口标识，不引入第三方窗口或模态框依赖，也不修改后端。
