# 精简模式文本编辑弹窗遮罩关闭设计

## 目标

精简模式中的文本编辑弹窗支持点击弹窗外的空白遮罩关闭。该操作与点击右上角关闭按钮进入同一套关闭流程，未保存内容继续受到现有确认机制保护。

## 现状

`TextEditorDialog` 使用 `modal={false}`，使任务栏等弹窗外控件仍可交互；同时使用 `disablePointerDismissal`，避免这些外部交互自动关闭编辑器。直接删除 `disablePointerDismissal` 会让任务栏点击、焦点移出和遮罩点击都触发关闭，可能与模式切换等操作产生重复动作。

## 设计

保留 `modal={false}` 和 `disablePointerDismissal`。通用 `DialogContent` 增加一个可选的 `onOverlayClick` 回调，并只把它绑定到自身渲染的 `DialogOverlay`。未传入时，其他 Dialog 的行为完全不变。

`TextEditorDialog` 将现有 `onClose` 传给 `onOverlayClick`。遮罩没有子交互元素，因此只有点击实际空白遮罩时调用关闭回调；点击弹窗内容、语法选择菜单、任务栏和其他位于遮罩上层的控件不会通过该回调关闭编辑器。

## 关闭行为

- 未修改的精简模式编辑器：点击遮罩后立即关闭。
- 精简模式独占且有未保存内容：点击遮罩后显示现有“保存 / 不保存 / 取消”确认框。
- 在确认框中选择取消：关闭确认框并保留原编辑弹窗和内容。
- 借用完整模式编辑实例的精简视图：沿用现有关闭规则，只隐藏精简视图并保留完整模式实例。
- 关闭按钮、`Esc`、保存、冲突处理和模式切换行为保持不变。

## 验证

- 组件测试确认点击文本编辑弹窗遮罩调用一次 `onClose`，点击弹窗内容不会调用。
- 工作区测试确认干净编辑器通过遮罩关闭。
- 工作区测试确认脏编辑器通过遮罩打开未保存确认，取消后编辑器仍存在。
- 运行完整前端测试、ESLint 和生产构建。
- 在真实浏览器中确认遮罩点击、未保存确认及任务栏交互均符合设计，且没有运行时错误。
