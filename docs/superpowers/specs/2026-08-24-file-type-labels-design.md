# 文件类型显示与排序设计

## 目标

文件浏览器的“类型”列不再直接显示后端枚举值。文件夹和特殊项目使用当前界面的语言显示，普通文件显示其实际扩展名；点击类型列排序时使用相同的显示规则。

## 显示规则

类型显示由一个纯前端函数统一生成：

- `directory`：中文显示“文件夹”，英文显示“Folder”。
- `file`：取文件名最后一个有效点号之后的内容，去掉点号并转换为小写。例如 `PHOTO.JPG` 显示 `jpg`，`archive.tar.gz` 显示 `gz`。
- 无有效扩展名的普通文件：中文显示“文件”，英文显示“File”。这包括不含点号的名称、仅由开头点号构成扩展分隔的点文件（如 `.gitignore`）以及以点号结尾的名称。
- `symlink`：中文显示“符号链接”，英文显示“Symbolic link”。不根据链接名称或目标推断扩展名。
- `other`：中文显示“其他”，英文显示“Other”。

扩展名只根据 `Entry.name` 计算，不读取 MIME 类型、文件内容或链接目标。

## 结构

新增一个独立的类型格式化模块。它接收文件条目和最小化的本地化标签集合，返回最终显示字符串。文件行和文件列表排序都调用该函数，避免显示与排序分别维护规则。

国际化字符串新增文件夹、无扩展名文件、符号链接和其他项目的类型标签。操作菜单中现有的软链接动作文本保持不变。

## 排序

- 名称、大小和修改时间排序行为不变。
- 类型排序使用格式化后的显示类型作为第一排序键，并使用现有自然语言比较器。
- 现有文件夹分组规则保持不变：文件夹始终位于其他项目之前。
- 显示类型相同的项目继续按文件名进行自然排序，保证结果稳定且可预测。
- 切换界面语言后，类型显示和类型排序键同步使用新语言。

## 影响范围

- 完整模式和精简模式共用文件行与排序实现，因此同时生效。
- 不修改后端浏览接口、条目数据结构、文件图标、选择、打开、拖拽、复制或重命名逻辑。
- 类型列宽度与表格布局保持不变；过长的英文类型沿用单元格现有布局行为。

## 验证

- 纯函数测试覆盖普通扩展名、大小写、复合扩展名、点文件、无扩展名、尾随点号、文件夹、符号链接和其他项目。
- 文件行组件测试分别验证中文与英文标签。
- 文件列表测试验证类型排序按显示值执行、同类型按名称排序且文件夹仍优先。
- 运行完整前端测试、类型检查、生产构建和真实浏览器检查，确认完整与精简模式显示一致。
