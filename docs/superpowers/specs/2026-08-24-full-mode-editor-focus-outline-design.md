# 完整模式文本编辑器聚焦框设计

> 本规范中“精简模式保留聚焦框”的规则已由 [文本编辑器内部聚焦框移除设计](./2026-08-24-text-editor-focus-outline-removal-design.md) 取代。

## 目标

移除完整模式文本编辑窗口内部被内容边界裁切的蓝色聚焦框，避免它与完整模式窗口已有的蓝色激活边框重复。文本编辑器的光标、当前行高亮、选区和键盘操作保持不变。

## 范围

- 仅影响完整模式桌面窗口中的文本编辑器。
- 精简模式文本编辑弹窗继续显示现有的编辑器聚焦框，用于提示键盘焦点。
- 不修改完整模式窗口外层的激活边框、标题栏状态、层级或聚焦逻辑。
- 不修改 CodeMirror 的选区、光标、当前行高亮、语法高亮及保存行为。

## 方案

保留当前通用的 CodeMirror 聚焦样式，并在完整模式桌面窗口作用域内增加更具体的样式覆盖，将编辑器自身的 `outline` 设为 `none`。这种方式以显示容器区分模式，不向文本编辑器组件增加模式参数，也不会改变精简模式弹窗或其他复用场景。

选择此方案而不是全局删除聚焦框，是因为精简模式没有完整模式桌面窗口的外层激活边框；选择样式覆盖而不是修改编辑器组件，是因为差异只涉及容器视觉，不需要引入组件状态或条件渲染。

## 交互与边界行为

- 完整模式文本编辑窗口获得焦点时，只显示窗口外层的蓝色激活状态，编辑区域边缘不再出现第二圈蓝框。
- 在编辑区域内点击和输入仍正常移动光标、更新当前行并显示文本选区。
- 在多个完整模式窗口之间切换焦点时，外层窗口激活状态继续按现有逻辑变化。
- 精简模式下聚焦编辑器时，内部蓝色聚焦框继续显示。

## 验证

- 增加样式测试，确认完整模式桌面窗口作用域内覆盖 CodeMirror 聚焦外框，同时通用聚焦样式仍然存在。
- 运行前端测试、代码检查和构建。
- 在浏览器中分别打开完整模式与精简模式文本编辑器，确认完整模式只剩窗口外层激活边框，精简模式仍保留内部聚焦框，并检查输入、选区和窗口切换不受影响。
