# 文本编辑器与语法高亮设计

## 目标

为 FileButler 增加常见文本和源代码文件的查看、编辑与保存能力。完整模式中的文本文件以独立应用窗口打开，精简模式继续使用页面级弹窗；编辑器提供常见语言语法高亮，同时保护编码、换行、未保存内容和外部修改，避免误写或覆盖文件。

本功能复用现有认证、映射根目录、窗口管理器、任务栏和模式切换结构。文本读取与保存是同步的单文件操作，不创建后台任务，也不出现在“任务进行中”侧栏。

## 已确认的产品决策

- 编辑器采用 CodeMirror 6，不嵌入完整 VS Code、Code OSS 或 code-server。
- 已适配的文本文件双击后直接打开；不增加“用文本编辑器打开”右键菜单。
- `.svg` 继续进入图片预览，不默认作为文本打开。
- 完整模式使用独立应用窗口，每个文件有一个任务栏按钮；精简模式使用页面级弹窗。
- 同一浏览器中，同一个 `rootId + relativePath` 不创建重复编辑实例。
- 支持编辑和手动保存，不自动保存。
- 支持 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE/BE 和 GB18030，并按原编码保存。
- 原始文件不超过 2 MiB 时启用语法高亮；大于 2 MiB 且不超过 10 MiB 时使用纯文本编辑；超过 10 MiB 时只显示无法打开提示，不提供下载入口。
- 保存时检测外部修改；发生冲突时提供“取消、重新载入、仍然覆盖”。
- 未保存内容关闭时提供“保存、不保存、取消”；页面刷新或关闭浏览器时使用原生离开警告。

## 方案选择

### 采用 CodeMirror 6

CodeMirror 6 提供编辑状态、视口渲染、行号、撤销重做、查找替换、快捷键和可按需加载的语言支持。FileButler 只维护文件识别和“文件名或后缀到语言”的映射，不自行实现词法分析或语法高亮规则。

编辑器及语言包只在首次打开文本文件时动态加载。具体语言根据文件名按需加载，避免增加初始文件管理界面的必要资源。

### 未采用 Monaco Editor

Monaco 能提供更接近 VS Code 的编辑体验，但需要额外处理 Worker、资源分包和更大的运行时，同时其部分能力超出当前单文件编辑范围。FileButler 当前不需要补全、代码诊断或语言服务，因此 CodeMirror 更贴合范围。

### 未采用完整 VS Code 或 code-server

完整 VS Code 不是可直接放入现有 `WindowFrame` 的编辑器组件。集成它需要额外服务、目录挂载、认证、iframe 或独立页面，以及两套文件管理和快捷键体系，无法自然复用当前每窗口任务栏和模式切换逻辑。

## 后端架构

### 模块边界

新增独立文本文件模块，负责：

- 识别允许的文本文件；
- 验证文件大小和普通文件类型；
- 检测并转换文本编码；
- 识别换行格式；
- 生成文件版本标识；
- 条件保存和原子替换。

HTTP 处理器只负责请求解析、状态码和 JSON 响应。路径解析继续使用现有 `roots.Resolver`，并在读取和保存时使用 `ResolveForWrite` 的规范路径检查，拒绝映射根目录之外的符号链接目标。

### 认证

读取和保存接口均注册在现有 `RequireAuth` 路由组内，与 `/api/browse` 和 `/api/media` 使用相同会话 Cookie。未登录或 Cookie 失效时先返回 `401 unauthorized`；身份验证通过前不解析文件路径、不检查文件是否存在，也不返回文件元数据。

### 读取接口

新增：

```text
GET /api/text?rootId=<root>&path=<relative-path>
```

成功响应的数据结构包含：

```json
{
  "content": "...",
  "encoding": "utf-8",
  "lineEnding": "lf",
  "byteSize": 1234,
  "revision": "sha256:..."
}
```

`encoding` 取值为 `utf-8`、`utf-8-bom`、`utf-16le-bom`、`utf-16be-bom` 或 `gb18030`。`lineEnding` 取值为 `lf`、`crlf`、`cr`、`mixed` 或 `none`。

读取顺序如下：

1. 验证文件名在文本白名单中。
2. 解析并验证映射根目录内的规范路径。
3. 确认目标存在且是普通文件。
4. 根据文件元数据和有上限读取确认原始大小不超过 10 MiB。
5. 按 BOM 检测 UTF-8 或 UTF-16。
6. 无 BOM 且是合法 UTF-8 时按 UTF-8 解码。
7. 否则严格按 GB18030 解码。
8. 解码后若包含 NUL 或明显的二进制控制字符模式，则拒绝打开。
9. 对原始字节计算 SHA-256 版本标识。

UTF-16 不带 BOM 不自动识别。无法完成上述解码的文件返回不支持文本错误，不把替换字符写入编辑内容。

### 大小策略

阈值以打开时的原始文件字节数为准：

- `0–2 MiB`：允许加载对应语言模式。
- `>2–10 MiB`：允许编辑，但前端使用纯文本模式并显示降级提示。
- `>10 MiB`：返回文件过大错误，前端只显示提示，不显示下载按钮。

编辑过程中若文档长度超过高亮安全阈值，前端卸载语言模式并继续以纯文本编辑。保存时以重新编码后的实际目标字节数执行 10 MiB 上限；超限则拒绝写入，编辑内容继续留在浏览器内。

### 换行处理

单一换行格式的文件在保存时继续使用原格式。CodeMirror 内部按一个行分隔符管理文档，因此混合换行文件在打开时显示 `Mixed`，并选择出现次数最多的换行作为保存格式；次数相同时选择 LF。未修改的混合换行文件不会触发写入，第一次实际保存时会统一为选定格式。

### 保存接口

新增：

```text
PUT /api/text
```

请求包含：

```json
{
  "rootId": "data",
  "path": "src/main.go",
  "content": "...",
  "encoding": "utf-8",
  "lineEnding": "lf",
  "revision": "sha256:...",
  "force": false
}
```

请求体上限为 32 MiB，用于容纳解码后 UTF-8 JSON 可能产生的体积增长；服务端最终仍以目标编码后的实际字节数执行 10 MiB 文件限制。调用方不能借由请求中的 `encoding` 改成未支持编码。保存请求的 `lineEnding` 只接受 `lf`、`crlf` 或 `cr`；读取结果中的 `mixed` 和 `none` 必须先由前端按已确定规则转换成实际保存格式。

保存流程：

1. 重新执行认证、白名单、路径和普通文件检查。
2. 以规范目标路径为键串行化同一进程内的并发保存。
3. 在锁内重新读取当前原始字节并计算 SHA-256。
4. 当 `force` 为 `false` 且版本不一致时返回 `409 revision_conflict`，不写文件。
5. 按原编码、BOM 和选定换行方式编码新内容。
6. 验证编码后大小不超过 10 MiB。
7. 在目标文件所在目录创建临时文件，复制原文件权限位，写入并同步。
8. 关闭临时文件后原子替换规范目标，并同步目录。
9. 返回新字节大小和新版本标识。

保存规范路径而不是覆盖入口符号链接本身，因此指向映射根目录内文件的符号链接继续存在；指向根目录外的链接仍被拒绝。原子替换保留权限位，不承诺保留硬链接关系、扩展属性或 ACL。

`force: true` 只跳过版本比较，不跳过认证、路径、文件类型、编码、权限或大小检查。

### 错误映射

- `401 unauthorized`：未登录或会话失效。
- `404 not_found`：文件在读取或保存前已不存在。
- `409 revision_conflict`：文件内容与打开时版本不同。
- `413 file_too_large`：打开或保存内容超过 10 MiB。
- `415 unsupported_text`：后缀不支持、二进制内容或编码无法识别。
- `400 invalid_request`：目录、非法路径、编码或换行参数。
- `403 permission_denied`：操作系统明确返回权限错误。
- `500 operation_failed`：其他读取、同步或替换失败。

任一保存错误都不能清除浏览器中的编辑内容。

## 前端架构

### 文件识别与语言加载

新增纯函数模块维护文件名、后缀、显示语言和 CodeMirror 加载器映射。文件列表双击普通文件时按以下优先级分发：

1. 目录进入逻辑。
2. 已支持图片和视频进入媒体预览；因此 `.svg` 保持图片优先。
3. 已支持文本进入文本编辑器。
4. 其他文件不执行打开动作。

CodeMirror 核心编辑功能在首次文本打开时动态加载，具体语言扩展再按文件类型动态加载。语言模块加载失败只关闭高亮并提示降级，不影响纯文本编辑和保存。

### 编辑实例

文本编辑实例与窗口记录分离。实例保存：

- 实例 ID；
- 根目录 ID、相对路径和文件名；
- CodeMirror `EditorState` 或可恢复的运行时状态；
- 编码、换行、字节大小和版本标识；
- 加载、保存、错误和冲突状态；
- 是否启用语言高亮；
- 是否存在未保存修改。

CodeMirror `EditorView` 只属于当前可见容器，最小化或模式隐藏时销毁；编辑状态、选择和撤销历史保存在实例运行时中，重新显示时恢复。该运行时保持在内存中，不写入 localStorage、SQL 或后端草稿。

为避免继续扩大 `FileWorkspace` 的职责，文本实例转换和查找复用规则放入独立状态模块，异步读取与保存放入专用控制器或 Hook。`FileWorkspace` 只负责把文件打开事件、模式和窗口生命周期连接起来。

### 完整模式窗口

`windowManager` 新增 `textEditor` 窗口类型，通过 `instanceId` 关联文本实例。窗口复用现有 `WindowFrame` 的移动、八方向缩放、最大化、还原、最小化、聚焦和关闭能力。

- 每个文件有独立窗口和任务栏按钮。
- 标题和任务栏显示文件名；未保存时增加明确标记。
- 同一个 `rootId + relativePath` 再次打开时恢复并聚焦已有窗口。
- 不同文件可以同时编辑。
- 最小化不触发保存提示。
- 完整模式切换到精简模式时窗口和编辑状态继续保留在内存，返回后恢复。

### 精简模式弹窗

精简模式一次显示一个页面级文本编辑弹窗。它复用完整模式相同的编辑内容组件和保存流程，但不创建任务栏按钮，也不能调整窗口大小。

精简模式切换到完整模式时，如果当前弹窗有未保存内容，则显示“保存、不保存、取消”；保存成功或选择不保存后关闭弹窗并继续切换，取消则保持精简模式。如果弹窗没有修改，直接关闭并切换。

如果同一文件已有由完整模式保留的编辑实例，精简模式不得创建第二份独立内容；它临时显示已有实例。关闭该精简视图不关闭被完整模式窗口持有的实例，切回完整模式后继续显示原窗口。

当精简视图借用完整模式实例时，关闭视图只隐藏它，不执行“丢弃”也不删除实例；未保存标记和页面离开保护继续存在。切换回完整模式会直接恢复该窗口，不出现关闭确认。只有精简模式独占、没有完整模式窗口持有的实例，关闭弹窗或切换模式时才执行“保存、不保存、取消”流程。

### 编辑器布局和操作

编辑器内容区由三部分组成：

1. 顶部轻量工具栏：显示可见的“保存”按钮；保存中禁用重复操作。
2. CodeMirror 编辑区：行号、选择、撤销重做、查找替换、横向和纵向滚动。
3. 底部状态栏：语言、编码、换行格式、光标行列、文件大小和保存状态。

快捷键：

- `Ctrl/Cmd+S`：保存。
- `Ctrl/Cmd+F`：查找。
- CodeMirror 默认撤销、重做和查找替换快捷键继续生效。

首版不提供语言、编码或换行方式手动切换。状态栏只显示这些信息。

CodeMirror 使用等宽字体，并跟随 FileButler 当前明暗主题。新增按钮、状态、错误和确认文案同时提供中文与英文翻译，并保留可访问名称和键盘焦点管理。

### 未保存保护

实例在内容偏离最近一次成功读取或保存的基线后标记为未保存。成功保存或重新载入后更新基线并清除标记。

关闭未保存窗口或精简模式弹窗时显示：

- 保存：保存成功后继续关闭；失败时保持窗口。
- 不保存：丢弃该实例的修改并关闭。
- 取消：返回编辑器。

完整模式的关闭确认框位于所属文本窗口中央，并跟随窗口移动和缩放；精简模式使用页面级确认框。只要任一实例未保存，就注册 `beforeunload`，由浏览器显示原生离开警告。所有实例恢复干净后移除监听。

## 保存和冲突交互

保存按钮和快捷键调用同一动作。保存期间状态栏显示“正在保存”，并忽略重复保存请求。

保存成功后：

- 更新版本标识、字节大小和保存基线；
- 清除未保存标记；
- 状态栏显示保存成功；
- 刷新当前正在显示该文件父目录的文件浏览会话，使大小和修改时间更新。

版本冲突时，在所属窗口内显示：

- 取消：关闭冲突框并保留本地内容。
- 重新载入：用磁盘最新内容、编码、换行和版本替换本地内容。
- 仍然覆盖：以 `force: true` 重试当前内容。

文件被删除或重命名、权限不足、内容超限、会话失效或原子写入失败时，编辑器继续保留本地内容和未保存标记。语言加载失败则退回纯文本模式，不视为文件读取失败。

## 与现有功能的关系

- 文本保存不创建 Job，不写 SQL，不出现在任务侧栏。
- 文本编辑窗口与来源文件窗口生命周期独立；来源窗口导航、最小化或关闭不关闭编辑器。
- 文件操作在编辑器打开后重命名或删除目标时，编辑器不会自动追踪新路径；下一次保存返回不存在错误。
- 模式切换沿用现有完整模式窗口保留策略，并对精简模式未保存弹窗增加显式保护。
- 媒体预览顺序保持在文本识别之前，确保 `.svg` 行为不变。

## 明确不包含

- 新建文本文件、另存为或下载。
- 自动保存、版本历史、草稿持久化或刷新恢复。
- 自动补全、语言服务器、代码诊断、格式化或运行代码。
- 多标签编辑器、集成文件树、终端或扩展系统。
- 未知后缀右键强制打开。
- 将 `.svg` 默认改为文本编辑。
- 超过 10 MiB 的流式文本查看器。
- 手动选择或转换编码和换行格式。

## 测试

### 后端

- 未登录读取和保存均返回 `401`，且不泄露路径状态。
- 相对路径越界、绝对路径、未知根目录和符号链接越界被拒绝。
- 目录、不存在文件、未知后缀和 `.svg` 被拒绝。
- 普通后缀和特殊文件名白名单完整覆盖。
- 2 MiB 和 10 MiB 边界行为正确。
- UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM 和 GB18030 可读取并按原编码往返保存。
- BOM、单一换行格式和权限位保持；混合换行按明确规则归一化。
- NUL、二进制控制模式和无效编码被拒绝。
- SHA-256 版本冲突不写文件，强制覆盖仍执行所有其他检查。
- 并发保存串行化，成功后返回新版本。
- 临时文件写入、同步或替换失败时原文件不被截断。

- 所有文件名、后缀和语言映射均有表驱动测试。

## 验收标准

- 未登录用户不能读取、探测或保存文本文件。
- 适配文件双击后在正确模式的编辑器中打开，`.svg` 和未知文件行为不变。
- 常见语言正确高亮，较大文件安全退回纯文本，超限文件只提示。
- 完整模式窗口拥有统一窗口能力和独立任务栏按钮，同文件不重复打开。
- 支持手动保存并保持原编码、BOM、单一换行格式和权限位。
- 外部修改不会被静默覆盖，用户可以取消、重新载入或明确强制覆盖。
- 任何保存失败都不丢失浏览器中的编辑内容。
- 未保存窗口关闭、模式切换和页面离开均有保护。
- 文本操作不进入后台任务系统，现有文件管理和媒体功能不回归。
