# SuperRename 自动媒体整理设计

日期：2026-08-27  
状态：已批准

## 概述

FileButler 新增 SuperRename：面向“当前目录包含大量一级子文件夹，每个子文件夹内有图片、视频及其他杂项”的自动整理工作流。

SuperRename 对每个一级子文件夹分别处理：直属图片按自然顺序重命名为纯数字名称；直属视频按独立自然顺序重命名为带 `V` 前缀的数字名称，并移动到该子文件夹内的“视频”目录。其他文件、更深层目录、符号链接和特殊条目不处理，但会在预览中醒目标出。用户可在统一树表中按文件夹或单个文件取消操作；选择变化只重排对应子文件夹中的对应媒体类型。

精简模式使用模态弹窗，完整模式使用新的自由桌面应用窗口。两种模式共用同一套 SuperRename 内容、后端规划规则、后台任务和 SSE 任务状态。

## 背景与现有架构

当前项目已演进到 v0.2.1，相关基础包括：

- 精简双栏模式和完整桌面多窗口模式。
- 带判别类型的统一窗口记录，现有应用包括文件管理器、PowerRename、媒体预览和文本编辑器。
- PowerRename 已抽取为可复用内容：精简模式包装为弹窗，完整模式包装为独立窗口。
- 后台任务使用内存存储，状态通过 SSE 推送；终态后刷新可见文件会话。
- 文件操作与重命名分别拥有规划和执行流程，但现有 PowerRename 只能对一份扁平列表连续编号，现有操作接口也不能安全表达“每个目录重新编号 + 创建目录 + 移动并改名”的组合任务。

因此，SuperRename 作为独立后端子系统实现，并复用通用窗口、任务存储和 SSE，不由前端串联多个现有任务。

## 目标

- 从任意真实目录启动，不依赖当前文件选择。
- 扫描当前目录的每个真实一级子文件夹，但不递归更深层目录。
- 在每个一级子文件夹内分别识别、排序和编号图片与视频。
- 根据当前勾选数量自动计算编号宽度，最少两位。
- 把视频移动到“视频”目录，并在同一个任务中完成重命名。
- 提供树形预览、文件夹三态选择、逐文件选择、局部即时重排和清晰冲突提示。
- 执行前由服务端重新扫描，拒绝过期或被篡改的计划。
- 使用组内暂存和回滚，安全处理目标名称正被另一待改名源文件占用的情况。
- 在精简模式和完整模式中提供与 PowerRename 一致的产品形态。
- 面向大量子文件夹保持可接受的扫描和交互性能。

## 非目标

初版不包含：

- 递归处理一级子文件夹内的更深层目录。
- 处理当前目录直属文件。
- 让用户编辑匹配表达式、替换模板、媒体扩展名列表、视频目录名或前缀。
- 扫描或重新编号已有“视频”目录中的内容。
- 自动恢复进程被强制终止后遗留的暂存目录。
- 跨根目录、跨文件系统移动。
- 将 SuperRename 草稿或窗口状态持久化到刷新后的浏览器会话。
- 把现有 PowerRename、普通重命名或文件操作重构为通用混合操作图。

## 已确认的产品规则

### 启动范围

- SuperRename 作用于文件窗口或精简栏当前所在的真实目录。
- 当前目录只是容器；它的直属文件不显示、不匹配、不处理。
- 当前目录下每个真实一级子文件夹形成一个分组。
- 符号链接目录不作为分组，也不跟随到映射根之外。
- 虚拟“所有位置”页面不能启动 SuperRename。

### 扫描深度

- 只读取每个一级子文件夹的直属条目。
- 更深层子文件夹不递归，作为不可展开的未匹配叶节点显示。
- 已有“视频”目录是唯一特殊子目录：可以作为视频目标复用，但不展开、不分类其中内容；只读取其直属名称以检查目标冲突。

### 媒体分类

扩展名匹配忽略大小写，重命名结果保留原扩展名文本及大小写。

图片扩展名：

- `.avif`
- `.bmp`
- `.gif`
- `.jpeg`
- `.jpg`
- `.png`
- `.svg`
- `.webp`

视频扩展名：

- `.m4v`
- `.mkv`
- `.mov`
- `.mp4`
- `.ogg`
- `.ogv`
- `.webm`

其他扩展名、符号链接和特殊文件均为未匹配项。

前后端媒体扩展名目录必须从同一份产品常量语义派生，并通过共享测试样例保持一致；不得继续在多个位置无测试地复制列表。

### 排序与编号

- 一级子文件夹按项目现有 Windows 风格自然排序展示。
- 每个分组内，图片和视频分别按原文件名自然排序。
- 图片和视频是两套独立序列，都从 1 开始。
- 图片目标主体等价于固定规则 `^.*` → `${start=1,padding=N}`。
- 视频目标主体等价于固定规则 `^.*` → `V${start=1,padding=N}`。
- `N = max(2, 当前子文件夹内当前媒体类型勾选数量的十进制位数)`。
- 示例：9 项使用 2 位，100 项使用 3 位，1000 项使用 4 位，10000 项使用 5 位。
- 图片目标保留在原一级子文件夹；视频目标位于该子文件夹的“视频”目录。

示例：

```text
写真 A/
  IMG_1.jpg      -> 01.jpg
  IMG_2.jpg      -> 02.jpg
  clip-1.mp4     -> 视频/V01.mp4
  clip-2.MKV     -> 视频/V02.MKV
```

### 选择与局部重排

- 所有匹配媒体默认勾选。
- 取消图片只重排同一子文件夹的图片。
- 取消视频只重排同一子文件夹的视频。
- 其他媒体类型和其他子文件夹的目标名称保持不变。
- padding 按对应媒体类型当前勾选数量重新计算。
- 未勾选媒体仍显示在原自然排序位置，目标显示为 `—`，状态显示为“已取消”。
- 文件夹复选框控制该组全部匹配媒体，并根据子项显示选中、未选或半选状态。
- 折叠分组不改变选择。
- 未匹配项复选框禁用。
- 冲突项可以取消勾选；只有仍勾选的冲突项阻止提交。

### “视频”目录

- 有勾选视频且“视频”不存在时，计划包含创建目录，树中显示“视频（将创建）”。
- “视频”已存在且是实际目录时复用，树中显示“视频（将复用）”。
- 不读取其更深层内容，不处理其已有文件；只检查直属目标名称是否被占用。
- “视频”路径已存在但不是目录时，该组所有勾选视频冲突。
- 该组没有勾选视频时，不创建“视频”目录。

### 无匹配项与展开状态

- 含至少一个匹配媒体的一级子文件夹默认展开。
- 完全没有匹配媒体的一级子文件夹仍显示，醒目标为“无匹配项”，默认折叠。
- 其他未匹配文件使用醒目的橙色状态。
- 更深层目录显示“不递归”，没有展开控件。
- `.filebutler-superrename-*` 内部暂存残留使用红色恢复警告，并阻止该组执行。

## 架构

### 总体结构

```text
FileWorkspace
├── File actions / context actions
├── Compact SuperRenameDialog
├── Desktop superRename WindowRecord
│   └── SuperRenameInstanceManager
│       └── SuperRenameContent
└── JobEventsStore / JobsSheet

POST /api/super-rename/preview
└── superrename.Scanner -> Inventory

client SuperRename projector
└── Inventory + selectedPaths -> visible Plan

POST /api/super-rename/jobs
└── Scanner -> authoritative Planner -> SuperRename Runner
    └── per-directory staging / finalize / rollback
```

### 后端包

新增 `internal/superrename`，主要边界为：

- `Scanner`：安全解析根目录和当前路径，读取一级子文件夹及必要的直属条目，输出与 UI 无关的库存清单。
- `Planner`：输入库存清单和勾选源路径，纯计算分组、padding、目标路径、无需变更项和冲突。
- `Executor`：按已验证分组计划执行暂存、目录创建、最终移动和回滚。
- `Runner`：连接内存任务存储，按文件记录进度，按目录边界处理取消和失败。
- HTTP handlers：解析请求、调用扫描/规划、创建任务并返回一致错误。

现有 `internal/rename`、`internal/ops` 和通用 `jobs.Runner` 不承担 SuperRename 的组内事务逻辑。

### 前端模块

新增独立模块：

- `superRename.ts`：媒体类型、库存、选择集合和投影计划的 TypeScript 类型及纯函数。
- `SuperRenameTree.tsx`：统一树表及文件夹/文件选择交互。
- `SuperRenameContent.tsx`：加载、摘要、刷新、错误、树表、取消和提交。
- `SuperRenameDialog.tsx`：精简模式模态外壳。
- `superRenameManager.ts` 或等价隔离控制器：完整模式实例状态、异步世代、提交锁和错误。

`FileWorkspace` 只负责捕获当前目录、创建或关闭实例、增加桌面窗口记录和注册任务 ID，不承载扫描与规划实现。

## API 设计

### 预览接口

```http
POST /api/super-rename/preview
Content-Type: application/json
```

请求：

```json
{
  "rootId": "media",
  "directoryPath": "写真合集"
}
```

响应概念结构：

```ts
type SuperRenameInventory = {
  rootId: string;
  directoryPath: string;
  generatedAtUnix: number;
  groups: SuperRenameInventoryGroup[];
};

type SuperRenameInventoryGroup = {
  path: string;
  name: string;
  images: SuperRenameCandidate[];
  videos: SuperRenameCandidate[];
  unmatched: SuperRenameUnmatched[];
  directOccupiedPaths: string[];
  videoDirectory: {
    status: "missing" | "directory" | "blocking-entry";
    path: string;
    occupiedPaths: string[];
  };
  recoveryResidues: string[];
};

type SuperRenameCandidate = {
  sourcePath: string;
  name: string;
  extension: string;
  mediaKind: "image" | "video";
};

type SuperRenameUnmatched = {
  path: string;
  name: string;
  kind: "file" | "directory" | "symlink" | "other";
  reason: "unsupported-extension" | "nested-directory" | "symlink" | "special";
};
```

实际 JSON 字段可以按 Go/TypeScript 现有命名习惯收敛，但必须保留上述语义。列表均由服务端自然排序，前端不得按平台默认字符串比较重新排序。

库存响应包含前端进行局部投影和冲突检查所需的全部直属占用信息，但不暴露映射根绝对路径。

### 创建任务接口

```http
POST /api/super-rename/jobs
Content-Type: application/json
```

请求：

```json
{
  "rootId": "media",
  "directoryPath": "写真合集",
  "selectedPaths": [
    "写真合集/写真 A/IMG_1.jpg",
    "写真合集/写真 A/clip-1.mp4"
  ]
}
```

安全规则：

- `selectedPaths` 不得重复。
- 每个路径必须是本次重新扫描得到的匹配媒体候选。
- 客户端不能提交目标路径、padding、媒体类型或操作类型作为可信字段。
- 服务端使用当前文件系统重新分类、自然排序、计算编号和验证冲突。
- 任一勾选项冲突或来源过期时不创建任务。

成功响应：

```json
{
  "data": { "id": "job_..." }
}
```

过期或冲突返回 `409 Conflict`，使用可区分的 `stale_preview` 或 `plan_conflict` 错误码。前端收到后自动重新请求预览，保留仍存在的选择交集，并要求用户重新确认。

## 扫描器设计

扫描流程：

1. 使用根解析器验证 `rootId + directoryPath` 位于映射根内且为真实目录。
2. `os.ReadDir` 当前目录，只把不跟随符号链接的实际目录作为一级分组。
3. 对每个分组执行一次 `os.ReadDir`。
4. 普通文件按扩展名分类为图片、视频或未匹配。
5. 其他实际目录作为未匹配叶节点；名为“视频”的目录记录为特殊目标容器。
6. 如果“视频”是目录，额外读取一次其直属名称用于目标占用检查，但不分类、不递归。
7. 检测 `.filebutler-superrename-*` 暂存残留并记录恢复阻塞。
8. 所有分组和候选使用现有 `internal/natsort` 排序。

扫描循环定期检查 `ctx.Err()`。读取目录项使用 `Lstat` 语义，不跟随文件或目录符号链接。

## 规划器设计

规划器是确定性纯函数。输入为库存与选择集合，输出为分组计划、树表行、摘要和冲突状态。

每个分组中：

1. 从自然排序后的图片列表过滤当前选择，计算图片数量和 padding。
2. 依次生成 `01.ext`、`02.ext` 等直接目标。
3. 对视频执行同样过程，生成 `视频/V01.ext` 等目标。
4. 未选择候选不生成目标，但其原路径仍属于已占用路径。
5. 目标等于自身来源时标记为 `unchanged`。
6. 目标不存在时为就绪。
7. 目标属于另一个已选择且会离开该路径的源文件时允许，由执行暂存解决。
8. 目标属于未选择候选、未匹配项、已有“视频”内容或阻塞条目时冲突。
9. 暂存残留使整个分组冲突。

摘要至少包含：一级目录总数、含匹配目录数、已选择文件数、未匹配项数、冲突数和将创建“视频”目录数。

Go 与 TypeScript 投影器使用同一组语言无关 JSON fixtures 验证输入与输出一致。服务端 Planner 始终是提交权威。

## 前端界面

### 入口

- 操作栏在 PowerRename 后显示 SuperRename 独立按钮。
- 当前为真实目录时启用，不依赖选择数量。
- 完整模式右键菜单显示同一入口；无论右键命中哪一行，都作用于当前目录。
- 虚拟根页面禁用。

### 精简模式

- 使用单个大尺寸模态框。
- 打开后立即请求扫描并显示加载状态。
- 点击遮罩、取消或 Escape 可关闭；提交期间禁止关闭。
- 同一时间只有一个精简模式 SuperRename 实例。

### 完整模式

窗口管理器增加：

```ts
type SuperRenameWindowRecord = BaseWindowRecord & {
  kind: "superRename";
  instanceId: string;
};
```

行为：

- 每次调用创建一个新实例和新窗口，不复用已有窗口。
- 标题为 `SuperRename — 当前目录名`，使用与 PowerRename 区分的图标。
- 复用移动、八方向缩放、层级、最小化、最大化、恢复、关闭和任务栏行为。
- 多个实例的库存、选择、展开状态、异步扫描和提交锁彼此隔离。
- 来源文件窗口之后导航、改选、最小化或关闭不改变固定的 `rootId/path`。
- 切到精简模式时隐藏但保留完整模式实例；切回后恢复草稿和窗口状态。
- 页面刷新不恢复实例。
- 活动 SuperRename 不产生 `activeSessionId`，不参与文件剪贴板快捷键或文件拖放目标。

### 统一树表 A

顶部摘要：

- 目录数。
- 已选择文件数。
- 未匹配项数。
- 冲突数。
- “刷新预览”。
- “执行 N 项”。

树表列：

- 当前项目。
- 计划结果。
- 状态。

文件夹行包含：展开控件、三态复选框、目录名、图片数量、视频数量、两类 padding 和组状态。

文件行包含：复选框、媒体/文件/目录图标、原名称、目标相对路径和状态。状态颜色：

- 正常重命名或移动：蓝色/绿色。
- 无需变更：中性绿色。
- 已取消：弱化灰色。
- 未匹配或不递归：醒目橙色。
- 冲突或恢复残留：红色。

含匹配媒体的组默认展开；无匹配组默认折叠；用户可手动改变。更深层目录没有展开控件。

### 刷新与异步一致性

- 每次扫描使用递增世代或 `AbortController`，只有最新响应能更新实例。
- 刷新时保留仍存在源路径的勾选状态。
- 新出现的匹配媒体默认勾选。
- 消失项移除。
- 仍存在分组保留手动展开状态；新含匹配分组默认展开，新无匹配分组默认折叠。
- 刷新失败保留旧库存和选择，只显示错误。
- 勾选变化只重算目标分组的目标媒体序列，并保持滚动位置。

## 任务与执行

### 任务模型

- 任务类型为 `super_rename`。
- `SourceRootID` 为来源映射根。
- `ProgressTotal` 为勾选文件数；创建目录不计数。
- 使用现有内存任务存储、SSE、任务面板和终态刷新机制。
- SuperRename 使用专用 Runner，因为通用 `jobs.Runner` 的逐项执行模型不能保证组内暂存和回滚。

### 每组执行算法

1. 再次检查上下文和取消状态；取消只在组之间生效。
2. 校验该组计划涉及的源和目标仍符合创建任务时的权威计划。
3. 跳过无需变更项；如果没有实际变化，直接记录组内项目成功。
4. 在一级子文件夹内创建唯一 `.filebutler-superrename-<job>-*` 暂存目录，保证与源和目标同文件系统。
5. 在暂存目录写入源、暂存和目标映射清单，便于失败诊断和人工恢复。
6. 把所有需要变化的源文件原子移动到唯一暂存名，先腾空组内源名称。
7. 如有勾选视频，验证并创建或复用“视频”目录。
8. 从暂存位置依次移动到最终图片和视频目标。
9. 成功后删除映射清单和空暂存目录，并按文件记录成功进度。

### 失败与回滚

- 组内任一步失败后，执行器按映射清单把已到最终位置或仍在暂存位置的文件尽力移回原路径。
- 如果“视频”是本次创建且回滚后为空，则删除它；已有目录绝不删除。
- 回滚成功后清理暂存目录，该组所有勾选文件记录失败，继续下一个一级子文件夹。
- 回滚失败时保留暂存目录和映射清单，错误信息包含其相对路径；不得静默覆盖或删除无法确认的文件。
- 任一组失败使最终任务为 `completed_with_errors`。
- 取消请求在当前组完成或回滚后生效，剩余组不开始。
- 服务进程被强制终止时无法保证自动回滚。后续扫描检测暂存残留，阻止该组再次执行并提示人工检查；自动恢复留待后续版本。

## 冲突与过期处理

预览阶段只基于扫描库存显示冲突。提交阶段重新扫描，处理以下变化：

- 勾选来源已不存在。
- 来源不再是直属普通媒体文件。
- 媒体扩展名或自然排序集合变化。
- 新文件占用了图片目标。
- “视频”目录类型变化。
- 新内容占用了视频目标。
- 出现内部暂存残留。

任何变化造成冲突时，不创建任务。前端收到 `409` 后自动刷新库存并提示重新确认；不会在用户未确认新计划时静默执行。

运行期间发生权限、磁盘、只读文件系统或其他 I/O 错误时，按组回滚并由任务面板显示失败计数和首个错误。

## 安全边界

- 所有请求使用 `rootId + relativePath`，从不接受绝对路径。
- 当前目录、一级分组、每个来源、暂存位置和目标均通过根解析器验证。
- 扫描不跟随符号链接。
- 服务端只接受重新扫描库存中的候选源路径。
- 目标路径完全由服务端规则生成。
- “视频”名称是固定的单个路径段，不接受客户端覆盖。
- 暂存目录使用随机唯一名称和仅服务进程需要的权限。
- 执行使用同文件系统内的 `os.Rename`，不降级为复制后删除。
- 任何目标占用都在移动源之前完成权威校验。

## 性能设计

- 扫描复杂度只与当前目录一级子文件夹、其直属条目以及已有“视频”目录的直属名称数量相关，不递归。
- 扫描和执行循环定期响应 context 取消。
- 前端库存按分组存储，选择变更只投影一个分组的一种媒体。
- 树表只渲染展开组的子行；无匹配组默认折叠。
- 初版不引入新的树表或虚拟列表依赖，也不设置任意项目数量上限。
- 多实例扫描结果通过实例 ID 和请求世代隔离。

## 错误状态

界面至少区分：

- 扫描失败：保留已有预览，可刷新重试。
- 无匹配项：允许查看树，但执行按钮禁用。
- 所有匹配项已取消：执行按钮禁用。
- 当前选择冲突：红色标记，执行按钮禁用。
- 提交计划过期：自动刷新并要求重新确认。
- 创建任务失败：保留实例和选择，可重试。
- 运行时部分失败：窗口已关闭，任务面板显示 `completed_with_errors`。
- 暂存恢复残留：组级红色阻塞，显示相对路径和人工检查提示。
