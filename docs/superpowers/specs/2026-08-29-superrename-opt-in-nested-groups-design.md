# SuperRename 深层目录按需参与设计

## 背景

现有 SuperRename 只把当前目录的真实一级子文件夹视为可执行分组。分组中的直属图片和视频可以预览、选择和重命名；更深层的真实目录只作为不可选择的“未递归”项目显示。

本设计扩展该模型：任意深度的真实子目录都可以由用户逐层加载并主动加入 SuperRename，但深层目录默认不参与。每个启用的目录仍然只处理自己的直属图片和视频，目录之间保持独立编号、独立事务和独立执行按钮。

本设计是对 `2026-08-27-superrename-design.md` 的增量修订。未被本设计明确替代的媒体分类、编号、冲突、事务、窗口和 SSE 规则继续有效。

## 目标

- 一级分组保持当前默认行为：打开预览时加载，匹配媒体默认全选。
- 任意深度的真实子目录都能在同一树中逐层发现。
- 深层目录默认不参与；展开只加载，勾选才选择该目录的直属媒体。
- 勾选一个目录不自动勾选任何后代目录。
- 深层目录启用后使用与一级分组完全相同的图片、视频、padding、冲突和事务规则。
- 每个目录行始终显示固定在最右侧的“重命名”按钮。
- 初始预览成本不随整棵目录树大小增长；深层数据按需加载。
- 单目录提交后立即减小预览内容，同时保留仍需承载后代的树形上下文。
- 服务端对深层路径重新扫描和校验，不信任浏览器缓存。

## 非目标

- 勾选父目录后递归处理整棵子树。
- 处理符号链接指向的目录。
- 把已有的“视频”目标目录及其后代再次视为 SuperRename 分组。
- 一次请求递归返回所有深层媒体。
- 持久化刷新浏览器后的深层目录加载和选择状态。
- 对单个超大目录增加虚拟滚动；本次通过按需加载、折叠和逐组移除控制总体 DOM 规模。

## 已确认的交互规则

1. 深层目录默认未加载、未选择、未参与任务。
2. 展开深层目录会加载其直属库存，但不会自动选择媒体。
3. 勾选未加载的深层目录会先加载，然后全选该目录的直属图片和视频。
4. 勾选一个目录不会改变任何后代目录的状态。
5. 加载后可以像一级分组一样单独勾选或取消图片、视频。
6. 深层目录的“重命名”按钮始终存在；不可执行时保留按钮并禁用。
7. 某层执行成功后移除该层媒体；若仍有后代，保留精简祖先行，直到后代清空后再剪枝。

## 总体架构

```text
POST /api/super-rename/preview
└── 扫描当前目录的一级分组
    └── 每个分组返回直属媒体、未匹配项和直属子目录引用

POST /api/super-rename/group-preview
└── 安全校验 scope + groupPath
    └── 只扫描该目录的直属媒体、未匹配项和下一层目录引用

SuperRenameManager
├── 按路径缓存目录节点和加载状态
├── 维护每组选择意图、文件选择、展开和完成状态
├── 对同一路径的加载与提交去重
└── 将已加载节点投影为递归树表

POST /api/super-rename/jobs
└── 从 selectedPaths 推导实际分组路径
    ├── 安全重扫每个唯一分组
    ├── 服务端 Planner 重新编号和检查冲突
    └── 现有 Runner / Executor 按目录事务执行
```

现有 `Executor.ExecuteGroup` 已使用 `PlanGroup.Path` 解析目录，并不依赖分组深度，因此任意深度目录继续使用同一事务实现，不新增递归执行器。

## 服务端库存模型

新增轻量目录引用：

```go
type DirectoryRef struct {
    Path string `json:"path"`
    Name string `json:"name"`
}
```

`InventoryGroup` 增加：

```go
ChildDirectories []DirectoryRef `json:"childDirectories"`
```

每个 `InventoryGroup` 仍只描述一个目录的直属状态：

- `Images`：直属图片。
- `Videos`：直属视频。
- `Unmatched`：直属不支持文件、符号链接、特殊条目和恢复残留。
- `ChildDirectories`：可继续检查的直属真实目录。
- `DirectOccupiedPaths`：全部直属占用路径，包括 `ChildDirectories`。
- `VideoDirectory`：该组自己的特殊“视频”目标容器。
- `RecoveryResidues`：该组内未完成的 SuperRename 暂存数据。

普通真实子目录不再同时出现在 `Unmatched` 中。符号链接目录仍是不可选择的未匹配项。`.filebutler-superrename-*` 恢复目录仍作为恢复阻塞处理，不进入 `ChildDirectories`。

`ChildDirectories` 使用现有 Windows 风格自然排序。它只包含路径与名称，不预先包含媒体数量，从而避免递归读取。

## 接口设计

### 初始预览

现有接口保持：

```http
POST /api/super-rename/preview
```

请求仍为：

```json
{
  "rootId": "media",
  "directoryPath": "albums"
}
```

响应中的 `groups` 仍是当前目录的一级真实子文件夹。每个分组已经加载，并带有 `childDirectories` 引用。

### 深层目录检查

新增：

```http
POST /api/super-rename/group-preview
```

请求：

```json
{
  "rootId": "media",
  "directoryPath": "albums",
  "groupPath": "albums/A/chapter-01"
}
```

- `directoryPath` 是打开该 SuperRename 实例时固定的作用域。
- `groupPath` 必须是该作用域下的严格后代真实目录。
- 响应为一个 `InventoryGroup`，只包含 `groupPath` 的直属库存。
- 不返回绝对路径。

错误约定：

- 无效、越界或保留路径：`400 invalid_request`。
- 目录不存在：`404 not_found`。
- 权限不足：`403 permission_denied`。
- 请求期间目录类型变化：`409 stale_preview`。
- 其他读取错误：`500 operation_failed`。

### 创建任务

`POST /api/super-rename/jobs` 的客户端请求继续只包含：

```json
{
  "rootId": "media",
  "directoryPath": "albums",
  "selectedPaths": [
    "albums/A/photo.jpg",
    "albums/A/chapter-01/scan.jpg"
  ]
}
```

不新增可信目标名称、媒体类型或递归标志。服务端按以下方式构造权威库存：

1. 对每个 `selectedPath` 取直属父目录，得到唯一分组路径。
2. 验证每个分组是 `directoryPath` 下允许参与的真实目录。
3. 只重扫这些唯一分组的直属库存。
4. 将库存交给现有 Planner，并验证每个选择路径确实是对应分组的当前媒体候选。
5. 任一选择过期或冲突时不创建任务。

因此，创建任务的扫描成本与本次实际选择的分组数和直属条目数相关，不与未展开的目录树相关。

## 扫描与路径安全

初始 `Scanner.Scan` 保持非递归：读取当前目录，再读取每个一级分组一次。`scanGroup` 对直属真实目录的处理改为记录 `DirectoryRef`。

新增单组扫描入口，复用 `scanGroup` 的分类逻辑。调用前必须从已解析的 `directoryPath` 开始逐段执行不跟随链接的检查：

1. 规范化 `/` 分隔的相对路径并拒绝空段、`.`、`..` 和绝对路径。
2. `groupPath` 必须严格位于固定作用域之下，不能等于作用域本身。
3. 从作用域开始逐级 `Lstat`；每一级都必须是真实目录，任何符号链接都拒绝。
4. 禁止进入某个分组的特殊“视频”目录及其后代。
5. 禁止把 `.filebutler-superrename-*` 恢复目录或其后代作为分组。
6. 最终目录仍须通过根解析器验证位于映射根内。

“视频”目录继续只读取直属名称用于目标占用检查，不分类、不返回子目录引用、不递归。
这里的保留边界以每个可执行分组为准：作用域下名为“视频”的一级目录仍可作为普通一级分组；从一级分组开始，任一目录的直属“视频”子目录都只作为该目录的视频目标容器，不能再成为深层分组，也不能从其后代绕过校验。

扫描循环继续定期检查 `ctx.Err()`。路径验证和目录读取使用同一套单元测试覆盖 Linux 与 Windows 风格相对路径输入。

## 前端目录节点状态

前端在现有 `SuperRenameManager` 中增加按路径索引的目录节点。概念状态为：

```ts
type DirectoryLoadState = "unloaded" | "loading" | "loaded" | "failed";
type GroupSelectionIntent = "none" | "custom" | "all";

type SuperRenameDirectoryNode = {
  path: string;
  name: string;
  parentPath: string | null;
  depth: number;
  loadState: DirectoryLoadState;
  inventory: SuperRenameInventoryGroup | null;
  childPaths: string[];
  selectionIntent: GroupSelectionIntent;
  ownLayerCompleted: boolean;
  error: string | null;
};
```

实际实现可使用不可变对象表和路径数组，避免在 React 快照中原地修改 `Map` 或 `Set`。

### 初始状态

- 一级分组节点为 `loaded`，`selectionIntent = all`，沿用当前默认全选。
- 一级分组返回的深层目录引用创建为 `unloaded`，`selectionIntent = none`。
- 有匹配媒体的一级分组默认展开。
- 未加载的深层节点不产生候选文件选择，也不计入匹配媒体数。

### 加载

- 展开未加载节点时调用 `group-preview`，成功后保持 `selectionIntent = none`。
- 勾选未加载节点时先记住 `all` 意图，再调用接口；成功后选择全部直属媒体并展开。
- 同一路径同时只有一个加载 Promise；展开和勾选共享它。
- 请求携带客户端代次。刷新、关闭或更新请求后，晚到旧响应被忽略。
- 加载成功后把新的 `childDirectories` 合并为未加载子节点。
- 取消勾选或折叠不会删除已加载库存。

### 选择意图

单独记录选择意图，避免刷新时把默认未参与的深层媒体意外选中：

- 点击目录复选框选中：`all`，选择全部直属媒体。
- 点击目录复选框取消：`none`，取消全部直属媒体。
- 单独改变文件选择：有选择时为 `custom`，全部取消后为 `none`。
- 刷新时，`all` 组自动选择新发现的直属媒体；`custom` 只保留仍存在的明确选择；`none` 不选择新媒体。
- 后代目录拥有完全独立的意图，不受祖先变化影响。

投影器仍按每个节点内当前选中的图片和视频分别重排；更改一个节点不会重算其他节点或后代节点。

## 树表展示

表格继续使用“当前项目 / 计划结果 / 状态 / 文件夹操作”四列。“文件夹操作”表头和所有操作单元格保持右侧粘滞。

每个目录节点都有独立目录行：

- 展开控件。
- 三态复选框。
- 与层级对应的缩进和树形引导。
- 加载、选择、冲突或完成状态。
- 始终渲染的“重命名”按钮。

目录复选框只汇总和控制该目录的直属媒体，不汇总后代状态。即使后代存在选中项，祖先复选框也不会因此变成选中或半选；祖先行是否保留由树形结构状态单独决定。

按钮禁用条件：

- 节点未加载或正在加载。
- 该层没有选中媒体。
- 该层存在冲突。
- 该层正在创建任务。
- 该层已经完成，只作为结构祖先保留。

展开节点后，只渲染该层直属媒体、未匹配项和直属子目录。折叠节点会从 DOM 中移除后代行，但保留缓存状态。深层缩进允许表格横向滚动，右侧操作列不随横向滚动离开视口。

状态文案区分：

- 未加载、默认不参与。
- 加载中。
- 已加载但未选择。
- 就绪、部分选择、冲突。
- 本层已完成。
- 加载失败，可重试。

摘要中的目录数统计当前已发现的目录节点；匹配、已选、未匹配和冲突只根据已加载节点计算。

## 单目录与批量执行

### 单目录按钮

单目录按钮只提交该节点的直属已选媒体。请求进行中只锁定该节点，其他节点仍可加载、选择和提交。

创建成功后：

1. 记录 `jobID -> groupPath + submittedPaths + selectionIntent`。
2. 立即隐藏该层媒体和未匹配详情，释放大列表内容。
3. 设置 `ownLayerCompleted = true`。
4. 如果节点没有任何后代，立即移除节点。
5. 如果存在后代，保留精简结构行承载树形上下文。
6. 从该节点向上剪枝：只有“本层已完成且已无后代”的祖先才能移除。

这里的“后代”包括已经发现但尚未加载的目录引用。初版不提供“忽略并移除整条分支”操作；用户可以继续逐层审核，或关闭当前 SuperRename 实例来放弃剩余可选分支。

终态处理：

- `completed`：保持完成和隐藏状态。
- `completed_with_errors`、`failed`、`canceled`、`interrupted`：取消完成标记，重新检查该目录，并恢复仍存在的提交选择。
- 若终态事件先于创建响应到达，注册任务后立即从任务快照补查终态，避免永久隐藏。

### 底部批量按钮

底部按钮提交所有已加载节点中的已选媒体。服务端会按实际父目录形成多个事务分组，现有 Runner 顺序执行。未加载或未选择的深层目录不参与。

批量创建成功后继续沿用当前行为：关闭该 SuperRename 弹窗或窗口，并由任务面板展示总体进度。单目录按钮则保持窗口打开，以支持逐组审核。

## 刷新与并发

手动刷新分为两部分：

1. 重新请求初始预览，更新一级分组和它们的直属子目录引用。
2. 对当前仍存在且曾加载的深层节点重新请求单组预览。

深层刷新使用有上限的并发队列，默认同时最多四个请求，避免大量已展开目录瞬间压满服务。未加载过的节点不会因刷新而被递归加载。

刷新按照选择意图协调选择；已消失节点及其后代从缓存中删除。正在创建任务的节点不被刷新覆盖；任务创建结束后再处理挂起刷新。
同一实例内已经成功执行的 `ownLayerCompleted` 状态在刷新合并时保留，避免重新扫描到仍存在的目录后恢复已隐藏的本层内容。

单组过期或冲突只刷新对应节点并要求再次确认。初始作用域失效才升级为整个预览错误。

## 错误处理

- 初始预览失败：沿用全局错误和重试。
- 深层加载失败：错误显示在对应目录行；保留展开、勾选重试能力，按钮禁用。
- 深层目录在加载期间消失：移除该节点；若由用户勾选触发，显示简短错误提示。
- 权限变化：保留节点并显示权限错误，防止用户误以为目录为空。
- 创建任务 `409`：刷新对应节点，保留仍有效选择并要求重新确认。
- 单组后台失败：恢复该层，不影响其他已经提交或完成的目录。
- SSE 断线：沿用现有重连与权威快照机制，不新增轮询。

## 性能边界

- 初始扫描复杂度继续只与当前目录的一级分组及其直属条目相关。
- 每次深层加载只读取一个目录及已有“视频”目录的直属占用名称。
- 创建任务只重扫包含选择项的唯一目录。
- 折叠分支不渲染后代 DOM；成功提交会移除该层媒体行。
- 节点库存只缓存于当前 SuperRename 实例，关闭实例即释放。
- 不设置业务深度上限；文件系统路径长度、请求体限制、根边界和逐段安全检查构成实际限制。

## 测试策略

### Go

- 初始扫描返回直属子目录引用，但不读取其媒体。

- 父子目录同时选择时分别编号、分别形成事务，互不包含后代媒体。
- Executor 在任意深度目录中继续完成暂存、提交和回滚。

- 一级分组默认全选，深层引用默认未加载且未选择。

- 同路径加载去重、旧响应隔离、加载失败重试。
- 修改一个节点只重投影该节点的对应媒体分区。
- 单组成功后保留必要祖先并正确递归剪枝。

- 展开、选择、加载状态和错误文案具备可访问名称。
- 单组提交不关闭窗口，批量提交保持现有关闭行为。
- 大量折叠节点不会渲染未展开媒体行。

## 兼容与迁移
