# 连接源与链接创建设计

日期：2026-08-31
状态：已审核

## 概述

FileButler 新增一套类似 Link Shell Extension 的“选择来源，再到目标位置创建链接”工作流。用户在任意文件面板中多选普通文件或真实文件夹，通过右键菜单执行“选择源连接点”；随后可在其他目录、文件夹行或映射根目录上右键，通过“创建为…”二级菜单选择“硬链接”或“软链接”，也可手动“取消选定的连接”。

普通文件的硬链接直接指向同一文件对象。真实文件夹的“硬链接”采用硬链接克隆语义：重新创建目录树，其中的普通文件成为源文件的硬链接；目录树内已有的软链接不被跟随，而是在克隆树中按原关系重建。文件夹的“软链接”只创建一个指向整个文件夹的符号链接，不执行软链接克隆。

链接创建使用独立后端子系统，但复用现有内存任务中心、SSE 终态通知、文件栏刷新和预览视觉体系。大目录预览只展示顶层摘要，任务进度按实际计划条目计算。每个顶层源独立暂存、提交和清理，避免展示半成品目录。

## 背景与现有架构

当前项目已经具备以下基础：

- 紧凑双栏模式和完整桌面多窗口模式。
- 文件行多选、右键目标识别、映射根目录卡片及应用内复制/剪切板。
- 基于 Base UI 的右键菜单，但现有动作模型只支持扁平命令。
- `internal/ops` 已能对普通文件执行 `os.Link` 和 `os.Symlink`，紧凑模式工具栏也已有直接以另一栏为目标的软/硬链接按钮。
- 现有硬链接规划明确拒绝目录，软链接执行器始终写入服务进程看到的绝对路径。
- 通用任务执行器按扁平条目执行，不能表达文件夹克隆的组内暂存、逐项取消和失败清理。
- 浏览接口能显示软链接目标文本，但无法判断其实际目标类型；文件夹软链接不能双击进入，跨根文件软链接也无法通过现有根边界解析可靠打开。

因此，本功能不继续把递归链接语义塞入通用操作执行器，而是新增专用链接规划与执行边界。现有紧凑模式快捷按钮迁移到新边界，确保同一种链接在不同入口下具有一致语义。

## 目标

- 支持从一个文件面板选择一个或多个普通文件、真实文件夹，形成一次性连接源。
- 支持跨紧凑面板、跨桌面文件窗口和跨映射根目录选择目标。
- 提供鼠标悬停可展开、键盘可操作的“创建为…”二级菜单。
- 对普通文件创建硬链接，对真实文件夹创建硬链接克隆。
- 对普通文件或真实文件夹创建单个软链接。
- 软链接优先使用相对目标路径，无法表示时回退为绝对路径。
- 在预览阶段完成递归扫描、重名、文件系统、特殊条目和来源有效性检查。
- 大目录预览保持顶层摘要，任务中心仍显示实际条目进度。
- 每个顶层项独立暂存；失败或取消不留下可见的半成品。
- 让目标位于任一映射根内的文件和文件夹软链接可安全打开，同时继续阻止未映射路径访问。
- 保持现有复制/剪切板、任务 SSE、终态刷新和文件选择规则不变。

## 非目标

本版不包含：

- 目标重名时自动改名、覆盖或合并。
- 整批多选的全有或全无事务；已经提交的顶层项不会因后续项失败而回滚。
- 软链接克隆。
- 通过拖拽创建硬链接或软链接。
- Junction、挂载点、Reflink、快捷方式或链接关系可视化管理器。
- 跨浏览器刷新持久化连接源。
- 复制目录所有权、ACL、扩展属性或平台专有元数据。
- 把任意未配置路径暴露为可导航目标。
- 对顶层选中的现有软链接或特殊文件创建链接；它们会作为不支持来源在预览中报告。

## 已确认的产品规则

### 连接源选择

- 文件面板右键菜单新增“选择源连接点”。
- 右键已选条目时保留当前多选；右键未选条目时沿用现有行为，用该条目替换选择。
- 连接源来自一次文件面板选择，因此拥有同一个来源根目录和来源父目录。
- 再次执行“选择源连接点”直接替换旧连接源。
- 连接源与应用复制/剪切板是两份独立状态，互不覆盖。
- 连接源只存在于当前浏览器页面内；刷新、关闭标签页或重新打开页面会清空。
- 当前可见的连接源条目显示蓝色链条标记。标记不改变复选框状态，也不使用剪切状态的灰化效果。
- 菜单显示连接源数量，例如“取消选定的连接（12 项）”。

### 连接源生命周期

- 未选择连接源时，不渲染“取消选定的连接”和“创建为…”。
- “取消选定的连接”立即清空连接源及所有标记。
- 关闭预览、预览加载失败、计划冲突或创建任务失败均保留连接源，方便用户修正目标或重试。
- 后台任务创建成功后立即清空连接源，不等待任务终态。

### 右键菜单结构

连接命令位于复制、剪切、粘贴之后，并与后续重命名等动作分组：

```text
选择源连接点
取消选定的连接（N 项）     仅存在连接源时显示
创建为…                    仅存在连接源时显示
    硬链接
    软链接
```

- “创建为…”是真正的二级菜单，支持鼠标悬停、点击、左右方向键、Enter 和 Escape。
- 紧凑模式顶部工具栏继续保留原软链接和硬链接快捷按钮，默认以另一栏当前目录为目标。
- 顶部工具栏按钮仍是直接快捷入口：它从当前活动栏选择构造请求并打开同一套链接预览，不读取、替换或清空页面级连接源。
- 紧凑模式右键菜单移除旧的直接软/硬链接命令，只保留新的连接源工作流，避免出现两套相似入口。
- 完整模式文件窗口只通过连接源工作流选择跨窗口目标。

### 目标位置

- 在文件列表空白处右键：目标是当前目录。
- 在普通文件或其他非目录条目上右键：目标仍是当前目录。
- 在真实文件夹行上右键：目标是该文件夹内部。
- 在虚拟根目录卡片上右键：目标是该映射根目录。
- 来源和目标可以位于同一面板、不同紧凑面板、不同桌面文件窗口或不同映射根。
- 硬链接最终是否可跨根不依据根 ID 判断，而依据源文件与目标目录的实际文件系统身份判断。

### 预览与冲突

- 选择“硬链接”或“软链接”后先打开预览，不直接修改文件系统。
- 桌面模式在目标文件窗口内打开本地预览；紧凑模式使用全局模态预览。
- 预览每个顶层连接源显示一行。
- 普通文件显示一个计划条目；文件夹硬链接克隆显示将创建的目录数、硬链接文件数和重建软链接数。
- 后台进度总数按实际计划条目计算，而不是按顶层行数计算。
- 任一顶层项冲突都会阻止整批任务创建。
- 目标名称固定使用来源 basename；目标已存在时显示冲突，不自动改名、不覆盖、不合并。
- 创建任务时由服务端重新扫描和规划。预览后出现来源变化、目标占用或文件系统变化时返回最新冲突，不创建任务。

## 文件系统语义

### 普通文件硬链接

- 来源必须是实际普通文件，不能是目录、软链接或特殊文件。
- 目标路径为 `目标目录 / 来源 basename`。
- 来源文件与目标父目录必须位于同一实际文件系统或卷。
- 预览记录来源文件身份；执行前再次使用不跟随软链接的文件身份核对，避免路径被替换后链接到错误文件。
- 来源文件在原 inode 上发生内容修改不视为来源替换，因为硬链接本来就共享同一文件对象和后续内容变化。

### 文件夹硬链接克隆

- 顶层来源必须是真实目录，不跟随顶层软链接。
- 递归重新创建目录结构；每个普通文件通过系统硬链接指向源文件。
- 空目录会被创建。
- 每个普通文件单独校验与目标目录的文件系统身份；源树跨越其他挂载点且其中普通文件无法在目标卷建立硬链接时，该顶层项冲突。
- 目标目录位于来源目录内部时拒绝执行，避免创建自包含克隆结构。
- 新目录保留来源目录的标准权限位和修改时间。构建阶段先使用可写权限，子项完成后再应用最终目录元数据。
- 硬链接文件天然共享文件内容、权限和时间等 inode 元数据。

### 克隆树中的现有软链接

- 扫描和执行都使用 `Lstat` 语义，不递归跟随软链接，避免循环、重复展开和越过映射边界。
- 如果软链接的词法目标位于当前顶层来源文件夹树内部，则在该组克隆树中重映射到对应的克隆目标。
- 指向另一个顶层来源、未选择的相邻路径或其他外部位置的软链接都按外部链接处理，继续指向原目标。该规则让每个顶层组保持独立，避免另一组执行失败后破坏已经提交的克隆。
- 外部链接不会原样复制相对目标文本；服务端先按源链接父目录计算其词法绝对目标，再从克隆后的链接父目录重新生成相对目标，无法相对表示时才使用绝对目标。
- 重建软链接同样优先生成相对目标，无法表示时使用绝对目标。
- 损坏软链接按其目标文本和词法位置重建；不会为了验证目标而跟随它。
- Socket、FIFO、设备文件及其他特殊条目不复制。扫描到任意特殊条目时，该顶层文件夹冲突，整批任务不能创建。

### 普通软链接

- 顶层来源必须是实际普通文件或真实目录。
- 每个顶层来源只创建一个软链接；文件夹不会递归展开。
- 目标路径为 `目标目录 / 来源 basename`。
- 服务端优先计算从目标链接父目录到来源路径的相对路径。
- Windows 跨卷或平台路径规则导致无法计算相对路径时，回退到服务进程可见的绝对路径。
- 新创建链接的目标文本始终按最终链接位置计算。提交前，服务端以最终链接父目录解析该目标文本，并验证其规范目标等于预期来源；不能直接跟随暂存目录中的链接，因为相对目标在暂存位置下本来可能暂时不可达。运行环境之外的宿主机挂载布局仍由部署者保证一致。
- 现有紧凑模式软链接快捷按钮迁移后采用完全相同的相对优先规则。

## 架构

### 总体数据流

```text
FileWorkspace
├── page-local LinkSource
├── context action builder
│   ├── Pick link source
│   ├── Cancel link source
│   └── Create as… submenu
├── Compact LinkPreviewDialog
└── Desktop window-local LinkPreview

POST /api/links/preview
└── links.Planner -> top-level summaries + internal grouped plan

POST /api/links/jobs
└── links.Planner re-scan -> links.Runner
    ├── per-source staging container
    ├── item progress / cancellation
    ├── atomic final rename
    └── jobs.Store -> SSE terminal event -> visible-session refresh
```

### 前端状态和模块边界

新增纯数据类型：

```ts
type LinkSource = {
  sourceRootId: string;
  sourceParentPath: string;
  paths: string[];
  entries: Entry[];
  createdAt: number;
};

type LinkType = "hardlink" | "symlink";
```

- 新增 `web/src/linkSource.ts`，集中负责创建连接源快照、判断当前行标记和构造请求。
- `FileWorkspace` 持有页面级 `LinkSource`，与现有 `AppClipboard` 并列但不复用状态。
- 右键动作模型扩展为“命令或子菜单”的判别联合；工具栏继续只接收扁平命令。
- `PaneContextMenu` 递归渲染 Base UI `SubmenuRoot` 和 `SubmenuTrigger`，并保留现有动作 ID、分隔线、禁用和 destructive 样式。
- `LinkPreview` 使用独立响应类型，但复用现有预览表格、错误提示、按钮和窗口对话框视觉约定。
- 文件行通过根 ID 和相对路径判断是否属于当前连接源快照，只增加链条标记，不把快照重新写入选择集合。

### 后端包

新增 `internal/links`，主要职责为：

- `Planner`：解析请求、递归扫描、生成顶层摘要和内部组计划、检查冲突及来源身份。
- `PathMapper`：计算相对/绝对软链接目标，判断当前顶层组内部链接并映射到克隆树。
- `Executor`：在暂存容器内创建目录、硬链接和软链接，应用目录元数据并执行最终提交。
- `Runner`：直接连接 `jobs.Store`，按组处理进度、取消、失败清理和后续组继续执行。
- HTTP handlers：实现预览、重新规划、任务注册和稳定错误响应。

通用 `internal/ops` 保留复制、移动、删除和新建目录。前端不再通过通用操作接口提交硬链接或软链接；旧链接分支从通用操作类型和执行路径移除，避免绝对软链接与新语义并存。

## API 设计

### 预览接口

```http
POST /api/links/preview
Content-Type: application/json
```

请求：

```json
{
  "type": "hardlink",
  "sourceRoot": "photos",
  "sources": ["albums/A", "albums/readme.txt"],
  "destRoot": "backup",
  "destPath": "2026"
}
```

成功响应固定使用项目现有 `{ "data": ... }` 包装，其中 `data` 结构为：

```ts
type LinkErrorCode =
  | "target_exists"
  | "missing_source"
  | "source_changed"
  | "unsupported_source"
  | "special_entry"
  | "cross_filesystem"
  | "destination_inside_source"
  | "outside_root"
  | "invalid_path"
  | "operation_failed";

type LinkPreview = {
  type: LinkType;
  sourceRoot: string;
  destRoot: string;
  destPath: string;
  previewRevision: string;
  progressTotal: number;
  hasConflict: boolean;
  items: LinkPreviewItem[];
};

type LinkPreviewItem = {
  sourcePath: string;
  destPath: string;
  sourceKind: "file" | "directory" | "symlink" | "other";
  counts: {
    directories: number;
    files: number;
    symlinks: number;
  };
  conflict: boolean;
  errorCode?: LinkErrorCode;
  errorText?: string;
};
```

- `items` 只包含顶层摘要，不向浏览器返回递归步骤或服务器绝对路径。
- `previewRevision` 是服务端根据规范化请求、来源身份、递归清单、目标占用和文件系统身份计算的摘要，格式固定为 `sha256:<64 位小写十六进制>`；它不包含也不编码服务器绝对路径。
- `counts` 统计该顶层项实际计划创建的条目类型：普通文件硬链接为 `files: 1`，普通软链接无论来源类型均为 `symlinks: 1`，其余计数为 0。
- 对普通软链接，每个顶层项的实际进度单位为 1。
- 对硬链接克隆，`progressTotal` 是所有计划目录、普通文件和重建软链接的总数，包含每个顶层克隆目录本身。
- 请求中的路径只被视为来源选择，不被视为可信计划；服务端负责推导目标 basename、递归步骤和软链接目标。

### 创建任务接口

```http
POST /api/links/jobs
Content-Type: application/json
```

请求在预览请求基础上增加必填的 `previewRevision`：

```json
{
  "type": "hardlink",
  "sourceRoot": "photos",
  "sources": ["albums/A", "albums/readme.txt"],
  "destRoot": "backup",
  "destPath": "2026",
  "previewRevision": "sha256:a2a6160e00000000000000000000000000000000000000000000000000000000"
}
```

服务端必须重新规划并重新计算 revision，不接受客户端提交的摘要、计数、目标文件名、递归步骤或文件身份。`previewRevision` 只用于检测用户确认后计划是否变化，不作为文件系统操作的可信输入。

- 成功返回 `201` 和 `{ "data": { "id": "job_..." } }`。
- revision 不一致返回 `409 stale_preview`，任一当前计划冲突返回 `409 plan_conflict`；两者都携带当前顶层摘要和新的 revision，且不创建任务。
- 请求结构错误、未知根目录和非法路径返回 `400`。
- 未认证返回 `401`。
- 任务类型继续使用 `hardlink` 或 `symlink`，沿用任务中心现有中英文显示。

链接预览、规划和执行必须使用以下稳定错误码：

- `target_exists`
- `missing_source`
- `source_changed`
- `unsupported_source`
- `special_entry`
- `cross_filesystem`
- `destination_inside_source`
- `outside_root`
- `invalid_path`
- `operation_failed`

前端优先按错误码显示本地化信息，`errorText` 仅作为未知错误的后备详情，且不得包含服务器绝对路径。

创建任务时发生重新规划冲突，响应固定为：

```json
{
  "error": {
    "code": "plan_conflict",
    "message": "link plan changed"
  },
  "data": {
    "type": "hardlink",
    "sourceRoot": "photos",
    "destRoot": "backup",
    "destPath": "2026",
    "previewRevision": "sha256:f4bbad3e00000000000000000000000000000000000000000000000000000000",
    "progressTotal": 3,
    "hasConflict": true,
    "items": [
      {
        "sourcePath": "albums/A",
        "destPath": "2026/A",
        "sourceKind": "directory",
        "counts": {
          "directories": 1,
          "files": 2,
          "symlinks": 0
        },
        "conflict": true,
        "errorCode": "target_exists"
      }
    ]
  }
}
```

前端请求层为 `APIError` 增加可选 `data` 字段，使预览可以从 `409` 响应读取新的 `LinkPreview`；其他既有接口的错误处理语义不变。

服务端先计算当前预览，再比较 revision。revision 不一致时优先返回 `stale_preview`，即使当前预览同时存在冲突；revision 一致但计划有冲突时返回 `plan_conflict`。前端在两种情况下都用响应中的预览替换旧内容，并要求用户重新确认；有冲突时确认按钮保持禁用。

## 规划与来源一致性

规划器按请求中的顶层路径顺序生成摘要，同时拒绝空来源、根目录本身、重复路径以及父目录不同的来源。每个路径执行以下步骤：

1. 使用不跟随最终条目的安全解析验证路径属于来源根。
2. `Lstat` 顶层来源并判断普通文件、真实目录、软链接或特殊类型。
3. 推导最终目标 `destPath / basename(source)`，验证目标父目录和目标根边界。
4. 检查最终目标不存在。
5. 对硬链接普通文件检查文件系统身份并记录来源文件身份。
6. 对硬链接目录执行不跟随软链接的深度扫描，生成确定顺序的组计划和计数。
7. 对目录内每个普通文件记录文件身份并检查目标卷兼容性。
8. 记录目录身份、权限位和修改时间；记录软链接原始目标及内部/外部映射结果。
9. 遇到任意特殊条目、越界路径或不支持来源时，将整个顶层项标为冲突。

目录步骤使用稳定的父目录优先顺序创建；目录元数据应用使用子目录优先、父目录最后的逆序。来源身份应包含平台可用的文件 ID/inode、设备或卷身份以及条目类型。执行前核对路径仍指向同一对象；普通文件在同一对象上的内容和时间变化不使硬链接计划过期。

规划完成后，以稳定字段顺序序列化规范化请求、每个顶层摘要、递归相对路径、条目类型、来源身份、目录权限位与修改时间、软链接原始目标及映射结果、目标占用结果和文件系统身份，并计算 `previewRevision`。服务端绝对路径、错误文本和扫描时间不进入摘要。创建任务时相同输入必须产生相同 revision，任一会改变执行结果的来源或目标变化必须改变 revision。

硬链接克隆在每个顶层组开始构建前和最终提交前各重扫一次来源树，并比较相对路径集合、条目类型和文件身份。新增、删除、替换或改型均以 `source_changed` 终止并清理当前组；同一普通文件对象上的内容修改仍被允许。文件系统不提供跨目录树快照锁，因此最终重扫与原子提交之间仍是最佳努力边界，但任何实际使用到的条目都必须在操作前再次核对身份。

## 执行、暂存与取消

### 顶层组边界

每个顶层来源是一个独立组：

- Runner 按请求顺序处理各组。
- 当前组在第一个执行错误处停止，清理当前暂存容器，将该组尚未执行的计划条目标记为失败/跳过，然后继续后续组。
- 当前组成功提交后不会因后续组失败而回滚。
- 用户取消时停止当前组、清理其暂存容器并把任务标记为 canceled；此前已提交组保留。

### 暂存容器

- 在最终目标父目录中使用安全随机名称创建模式为 `0700` 的隐藏暂存容器，保证与最终目标位于同一文件系统。
- 容器内写入版本化内部标记，包含运行实例 ID、任务 ID 和最终 basename。
- 普通文件链接和软链接也先创建在暂存容器中，再原子改名到最终位置。
- 文件夹硬链接克隆完整构建在暂存容器子目录中，全部成功并应用目录元数据后再原子改名。
- 最终改名前再次确认目标不存在；并发创建导致占用时提交失败并清理暂存内容。
- 只有带有效内部标记的目录才会被当作 FileButler 暂存项。标记之外允许零个或一个固定名称的 payload，以覆盖最终提交后、容器清理前异常退出的窗口；出现其他顶层内容即视为无效。名称相似但没有有效标记的用户文件绝不隐藏或删除。

### 进度与异常退出

- Runner 在每个实际目录、硬链接文件或重建软链接成功或失败后记录一次进度，并在下一步前检查取消请求。
- 成功任务的 `progressDone` 最终等于 `progressTotal`。
- 运行时错误使任务以 `completed_with_errors` 终止；失败组中尚未执行的步骤以失败/跳过结果补齐进度，因此该终态的 `progressDone` 也必须等于 `progressTotal`，不会显示成仍在运行的非 100% 进度。失败/跳过步骤计入 `failedCount`，不伪装成成功。
- 用户取消可在计划未处理完时以 `canceled` 终止，此时允许 `progressDone < progressTotal`，但终态完全由 `status` 判断，不能由百分比推断。
- 正常失败、取消和 handler/runner 返回路径都必须执行 defer 清理。
- 浏览接口隐藏当前运行实例中带有效标记的暂存容器。
- 异常退出遗留容器通过旧运行实例标记识别；再次浏览其父目录或在该目录规划链接任务时惰性清理。
- 惰性清理只删除通过完整标记验证的暂存容器，不按前缀批量删除。

## 软链接解析与安全导航

### 路径解析职责

根解析器需要区分三类操作：

- 解析目录内容或打开目标：跟随路径并保证最终位置仍可映射到已配置根。
- 操作目录项本身：只解析并约束父目录，不跟随最终软链接，允许安全重命名或删除未映射软链接本身。
- 从绝对或规范路径查找映射根：在重叠根中选择包含关系最具体、路径最长的根，并返回该根内相对路径。

这一区分修复现有“未映射软链接不能安全删除，但浏览路径存在意外跟随风险”的不一致。手动输入穿过未映射软链接的路径必须拒绝访问（fail closed），不能借新功能扩大可访问范围。

### 浏览元数据

后端 `browser.Entry` 和前端 `Entry` 在现有 `symlinkTarget` 之外增加可选字段 `symlinkResolution`，其固定结构为：

```ts
type SymlinkResolution = {
  state: "mapped" | "unmapped" | "broken";
  targetKind?: "file" | "directory" | "other";
  targetRootId?: string;
  targetPath?: string;
};
```

- 非软链接不返回 `symlinkResolution`。
- `mapped` 表示目标成功解析且位于某个映射根，此时必须同时返回 `targetKind`、`targetRootId` 和 `targetPath`。
- `unmapped` 表示词法目标或解析链离开所有映射根；服务端不继续探测根外目标是否存在，也不返回目标类型或规范路径。
- `broken` 表示映射根内目标不存在、解析链损坏或出现软链接循环；不返回导航字段。
- 不向前端暴露新增的服务器绝对规范路径。
- 双击可映射文件夹软链接时，文件会话直接切换到目标根及相对路径，并记录一次正常历史访问。
- 双击可映射文件软链接时，编辑器或媒体预览使用目标根和目标路径读取；窗口标题仍以用户点击的链接名称为入口名称。
- 未映射或损坏软链接仍可选择、重命名和删除，但双击不执行导航或打开。

## 前端交互细节

- “选择源连接点”成功后显示本地化成功提示和数量。
- “取消选定的连接”是普通非 destructive 命令，不显示确认框。
- “创建为…”触发项显示右向箭头和正常悬停/焦点状态；子菜单保持与主菜单一致的尺寸、阴影和层级。
- 点击子菜单命令时固定当次目标快照并关闭菜单，再发起预览请求，避免菜单关闭后的右键目标引用变化。
- 预览加载期间显示骨架；旧响应不能覆盖较新的目标或链接类型请求。
- 预览标题、描述、计数、冲突和确认按钮全部本地化。
- 桌面文件窗口存在本地操作对话框时，现有文件快捷键隔离规则继续生效。
- 连接源存在时不会改变 Ctrl+C、Ctrl+X、Ctrl+V 或 Ctrl+A 的作用域。
- 任务创建成功继续调用统一任务注册流程；可见文件会话只在 SSE 终态后刷新，并保留各自滚动位置。

## 错误与竞态处理

- 预览请求失败：显示错误，保留连接源和目标窗口。
- 预览发现冲突：显示所有顶层摘要，禁用确认，保留连接源。
- 创建时返回 `stale_preview` 或 `plan_conflict`：使用服务端返回的新摘要与 revision 替换旧预览，要求用户重新确认。
- 创建任务网络失败或服务端拒绝：预览保持打开，连接源保留。
- 任务创建成功但执行期来源消失、权限变化或目标被占用：任务进入 `completed_with_errors`，当前顶层暂存项清理，其他顶层项按规则继续。
- SSE 断线沿用现有重连与终态合并规则；本功能不增加轮询。
- 页面刷新会清除连接源，但已创建后台任务继续运行并可由当前任务快照恢复显示。

## 验证

### 后端单元与集成测试

- 普通文件硬链接创建后使用 `os.SameFile` 或平台文件身份确认共享同一对象。
- 空目录、深层目录和文件/文件夹混合多选硬链接克隆。
- 目录权限位和修改时间恢复。

- 普通文件及文件夹软链接使用相对目标；平台无法相对表示时使用绝对回退。
- 同名目标、跨文件系统、特殊条目、顶层软链接、目标位于来源内部、重复来源及非法路径。
- 预览后来源被替换、删除或改变类型，创建任务拒绝或执行期安全失败。

## 变更组织

实现适合拆分为以下聚焦提交：

1. 安全路径解析与软链接目标映射。
2. 后端链接规划、API、暂存执行和任务运行。

每个提交都必须保持工作区中无关改动不变，并在相应风险范围内完成测试。
