# 115直链预览、自动扫码登录与窗口体验改进

## 目标与范围

落实用户新增的十项要求：统一红色删除按钮、修复115 PowerRename文件名错误、移除115文件栏额外蓝色聚焦框、更多菜单按右键分组、115直链预览、压缩包双击解压、移除精简模式顶栏阴影、独立可拖动进度窗口、统一115任务栏云图标，以及扫码确认后自动登录。

保留现有本地文件行为、后台任务生命周期与SSE终态刷新。按功能提交，不推送、不发布版本，不对用户真实网盘文件做未经指定范围的写入测试。用户已确认：直链无法内嵌时提供新标签页打开或直接下载，不自动使用FB中转；云端文本先做只读预览。

本次涉及预览数据来源和窗口交互接口，按架构级改动设计。书面设计确认后直接实施，不增加执行计划文档。

## 外观、菜单与双击

- 删除按钮与其他工具栏按钮使用相同边框、背景、尺寸和交互形式，保留红色图标及文字、禁用态和原确认逻辑；不是红色无边框文字按钮，也不改成整块红底。
- 移除115文件列表额外的整栏蓝色聚焦框，不取消键盘焦点能力，不删除按钮、输入框、选中项和拖放目标必要的状态提示，不修改普通文件面板的选中逻辑。
- “更多”和右键使用同一动作分组。过滤已显示在工具栏上的动作后保留组边界，空组不显示分隔线，首尾不显示分隔线，也不产生连续分隔线。包含复制/剪切/粘贴、连接点操作等适用组；115仍不显示连接点操作。
- 精简模式顶部菜单/工具栏去除阴影，保留布局、边框和按钮；不全局取消桌面浮动窗口阴影。
- 顶部任务栏中115窗口使用与桌面和窗口标题一致的云图标，不再回退到文件管理器图标。
- 115目录双击仍进入目录；受支持压缩包双击打开现有窗口内在线解压弹窗，固定源文件ID及目标目录，可填写密码并确认执行，不立即无确认创建解压任务。菜单与双击共用识别范围和执行入口。

## PowerRename文件名错误

当前异常文字来自Python `safe_name`。批量扫描会校验整个源目录的所有条目，即使只选中少数文件，因此还需要区分源条目读取、规则生成和最终写入校验，不能直接认定是用户替换表达式出错。

实施时先用可控数据复现，明确报错阶段和具体触发条件后修复。云端稳定ID与展示路径分开，不把云端原名称误用于本地文件路径拼接或磁盘访问。无关条目不应无差别阻断可安全执行的选中项；无法无歧义处理的源名称必须明确指出对应条目。新目标名称仍严格校验，不能通过删除安全校验掩盖问题。

保留冻结预览、执行前源ID/名称/父目录核对、目标不覆盖、名称互换与恢复记录。错误信息应能定位条目，但不暴露凭证。补充普通名称、中文括号、边界字符、无关兄弟条目和无效目标的回归测试。

## 115直链预览

### 选定方案

使用“FB鉴权并取得直链，浏览器直接访问115”的方式。复用现有媒体预览、文本显示和文件类型识别，不为云端复制另一套预览规则。相比统一302入口，直接返回URL更方便显示过期和不支持原因；不采用FB文件内容代理，因为这与用户避免服务器带宽瓶颈的目标冲突。

新增鉴权的只读直链接口，以115文件ID请求，由服务端校验条目并通过已有provider获取URL。FB只传递直链描述和必要展示元数据，不请求文件内容，不在预览中调用现有后台下载接口。使用当前浏览器User-Agent申请适配链接；只接受HTTP/HTTPS URL。

直链是临时授权信息：响应不缓存，不写入持久浏览器存储、不放入应用路由、不记录完整签名URL到日志；账号切换和窗口关闭时丢弃相应状态。Cookie和完整上游响应不得发送给浏览器。只返回明确允许的字段，不把SDK URL对象附带的任意请求头直接序列化。

### 浏览器行为与限制

- 图片、视频直接设置远程URL，沿用现有预览窗口和同目录上一项/下一项能力；切换时按文件ID取链接并忽略过期异步响应。媒体格式受原项目识别范围及浏览器解码能力约束，不增加服务器转码。
- 文本由浏览器直接请求115直链，以原有文本识别和体积限制展示只读内容；不启用本地保存接口，不将HTML等内容作为可执行页面插入FB页面。
- 预览窗口显示加载、失败和重试状态。失效链接可重新获取，但不能无限重试或悄悄转为中转下载。关闭窗口或切换文件中止不再需要的浏览器读取。
- 跨域、额外Cookie、上游限制、浏览器不支持格式等造成无法内嵌时，说明原因并提供可用直链的新标签页打开/直接下载入口；外链使用安全的新标签页属性。跨域下载不承诺浏览器一定遵从自定义下载文件名。
- 若取得的链接本身需要无法安全提供的Cookie等条件，则明确说明目前无法直连；不声称新标签页能解决所有鉴权限制，不向前端泄露账号Cookie，不自动中转。该边界不属于FB能够解除的浏览器或115限制。

SDK依据：[download_url说明](https://p115client.readthedocs.io/en/latest/reference/module/client.html)，部分直链带过期时间并要求匹配User-Agent或额外Cookie。具体使用已安装SDK支持的接口，真实可用性需要账号环境联调，模拟测试不得冒充真实直链验证。

## 独立可拖动进度窗口

保持JobEventsStore作为进度和窗口显示意图的来源，移除右下角固定网格堆叠方式。每个任务ID对应一个独立、非模态、可拖动窗口，有独立位置和前后层级；多个窗口同时显示，初始位置错开，屏幕缩小时约束到可操作范围。

复用现有窗口标题栏、拖动与聚焦机制中适用的部分，既支持桌面模式也支持精简模式；不为此重写整个桌面窗口管理器。窗口不吞掉其他文件窗口操作，拖动进度窗口不触发文件拖放。进度窗口不新增最大化、缩放等本次未要求的能力。

“取消”继续请求后端取消，并遵守不可取消阶段；“后台运行”和标题栏关闭只隐藏该窗口，任务仍继续。可以从任务面板重新打开同一任务的进度窗口，不重复创建同一任务窗口。成功或取消终态自动关闭；失败或部分失败保留错误供用户查看。浏览器关闭不终止任务，仍通过SSE更新，不增加任务轮询。

## 扫码确认后自动登录

现有后端已有 `login.check`，状态确认后会换取Cookie并保存，因此不需要用户在FB中再次确认，也不需要模拟点击115客户端确认按钮。

- 点击获取二维码成功后自动开始状态检查，页面显示“等待扫码”“已扫码，等待确认”等状态；取消“我已扫码，检查登录”的必需操作。只有115返回已确认并且服务端凭证保存成功后才进入文件列表。
- 正常按约2秒间隔检查，上一个请求结束后才启动下一个，禁止重叠。短暂网络故障采用有上限退避；二维码过期、用户取消、重新获取、窗口关闭、账号切换或成功登录后停止旧检查。持续无法确认时提示重新获取，不无限静默重试。
- 每次二维码有服务端生成的不透明会话标识，检查必须绑定对应会话。防止多个115窗口或重新获取二维码后，旧响应误用新二维码、重复换取凭证或覆盖账号。会话失效有明确状态，失效检查不能修改凭证。
- 登录成功沿用现有账号变化通知，使其他115窗口同步登录状态、账号名与根目录。保留有115后台任务时禁止切换账号的保护。
- 二维码状态检查是仅在登录期间运行的有限状态查询，不是文件任务轮询，也不是新增后台文件任务。任务状态仍由现有SSE负责。不额外引入整套登录SSE基础设施。
