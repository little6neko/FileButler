# SQLite 持久化与文件 SHA1 缓存

## 目标和已确认约束

统一使用 SQLite 保存 FB 账号、会话签名密钥、115 Cookie 和文件 SHA1。
保留后台任务并发、现有登录交互与传输进度，不增加移动后的整文件重复校验。

用户明确要求：产品不包含旧数据自动迁移代码、一次性导入脚本或旧格式兼容路径。
测试环境由开发者停服后手动转存现有值；此操作不进入项目。

本版不新增全盘扫描、哈希管理界面、自动去重删除、多账号 UI、Cookie 加密或任务历史持久化。

## 存储边界

- 新配置项 `database_file`，默认 `./data/filebutler.db`，相对配置文件目录解析。
- 删除产品中的 `auth_file`、`cloud115.credentials` 及对应旧文件读写实现。
- 监听地址、文件根目录、Python 路径等部署配置继续使用 YAML。
- Go 负责数据库初始化、访问和关闭；使用支持 CGO_ENABLED=0 构建的 SQLite 驱动。
- Python 不单独创建表或直接访问数据库，经现有私有标准输入输出通道调用限定的凭证和哈希存储操作。
- 新建空库可初始化；非空的无效库、损坏库或不支持的库版本应报错停止，不重建或默认为未初始化。
- 仅有当前 schema 的初始化和版本检查，不编写从旧 JSON/TXT 导入的机制。

选择一个数据库、按用途分表，便于整体备份；不采用多个独立数据库，也不让 Go/Python 各自维护一套存储规则。

## 数据划分

- `users`：现有管理员 ID、用户名、Argon2id 密码哈希。维持当前单管理员语义。
- `internal_settings`：会话签名密钥等内部值。创建管理员和生成签名密钥在同一事务内完成。
- `cloud_credentials`：服务标识、当前 Cookie、可用的账号标识及更新时间；保持当前单个115账号。
- `file_hashes`：来源、本地根目录标识及映射身份/115账号标识、相对路径/115文件 ID、SHA1、文件版本、取得来源和时间。

SHA1 统一验证为40位十六进制并规范化大小写，不作为文件记录主键。
本地文件版本包含设备号、inode、文件类型、大小、纳秒 mtime/ctime；缺少可靠版本信息时不复用。
本地根目录的实际映射也参与缓存范围，避免用户更改根目录配置后误用旧记录。
115记录按账号与文件 ID 隔离；接口返回的摘要与本地计算结果分别标注来源。
哈希表是可丢弃缓存，账号、密钥、凭证不是；清理缓存不得删除整个数据库。

## 账号和凭证

- 登录验证和会话签名算法保持现状，数据库只保存密码哈希，绝不保存明文密码。
- 115确认扫码后通过私有通道写入Cookie；写入失败不能向前端报告登录成功。
- 后端重启后从库读取Cookie；退出登录删除凭证记录并清除内存客户端。
- 保留任务运行期间禁止切换账号的保护。
- SQLite 不等于加密：本版Cookie和签名密钥在库内仍可读，拥有数据库读取权限即有泄露风险。
- 新建数据目录限制权限，数据库及其辅助文件限制访问；不放到文件浏览根目录或静态资源目录。
- 凭证不进入HTTP响应、URL、命令行参数、普通日志或测试输出。

## 私有通道与并发

扩展现有请求 ID 多路复用协议，让Python任务发起带关联 ID 的存储请求，并等待对应结果。
Go读取循环识别存储消息，分派限定操作，写回复时使用现有写入互斥。
不提供任意SQL执行接口，也不在前端暴露此通道。

存储处理不得等待尚未完成的云任务，不得在持有通道写锁时执行数据库I/O。
进度确认、取消、多个任务的结果与存储响应分别路由；子进程退出时释放等待者。

数据库启用WAL和有限的忙等待，事务只覆盖短小读写；哈希计算与网络传输不持有写事务。
多个任务仍同时传输，短暂的数据库写入互斥不是任务排队。
数据库必须置于本机文件系统，WAL文件不放在SMB/NFS目录。

## SHA1获取和复用

### 本地上传

1. 以安全打开的文件句柄取得文件版本，按来源和文件定位查询缓存。
2. 版本完整匹配才使用SHA1；否则沿用现有带进度的SHA1计算流程。
3. 计算前后核对版本，发生变化或取消时不写入有效缓存。
4. 已确认有效的摘要独立于上传结果，可供重试上传复用。
5. 复用摘要不跳过115要求的范围校验、上传过程中的源文件变化检查或服务端验证。

### 下载与115摘要

- 下载继续边写入边计算摘要，不重复读盘；只有完整下载并成功发布最终文件后才记录本地SHA1。
- 确认最终文件身份与版本，避免将下载摘要绑定到并发替换的文件。
- 保存浏览/属性查询已经返回的115文件SHA1；不为填表而额外遍历全盘或下载云端文件。
- 115服务端提供的摘要不自动视作任意本地文件的有效缓存。

### 变化和失效

- FB内的重命名、移动、删除、编辑、覆盖需维护或失效相关记录，目录操作覆盖子路径。
- 仅在能证明是同一未变文件的内部操作中同步路径；无法确认则失效，不为保留缓存增加整文件读取。
- 外部程序改动时，缓存查询的版本检查负责拒绝过期结果；外部改名允许缓存未命中。
- 设备号和inode不是永久身份，元数据匹配也不是抵抗恶意篡改的内容证明。
- 不用SHA1缓存授权删除文件，也不因此降低现有移动保护。
- 缓存读写异常可降级为重新计算/不缓存，并给出不含敏感信息的诊断；不得把已完成传输伪报为未完成而诱导重试。
- 凭证/认证写入失败则明确失败，不能采用缓存的静默降级方式。

## 测试环境切换（非产品功能）

确认8082无活动任务后停服，保留受限权限的旧文件备份，手动将用户名、密码哈希、签名密钥和已有Cookie转存新库。
不输出这些值，不通过命令行参数携带它们，不提交临时操作代码。
更新测试配置为 `database_file`，启动新服务；账号密码继续保持测试环境现值。
旧文件不被新版程序读取；备份仅用于人工回退，不提交Git。
保留签名密钥以尽可能维持有效会话。Cookie过期时正常提示重新扫码，不声称手动导入能恢复已失效凭证。

## 验证和交付

- 数据库创建、权限、重启、并发读写、非法库失败关闭。
- 管理员初始化互斥、密码哈希验证、重启登录、签名密钥保留及无旧文件回退。
- 115扫码存取、退出删除、持久化失败、账号隔离和通道并发/取消测试。
- SHA1缓存命中不重新整文件读取，版本变化/同路径替换失效，计算中变化或取消不污染缓存。
- 下载发布、内部重命名/移动/删除/编辑、跨根映射变化和云端摘要保存测试。
- Go、Python、前端现有回归和CGO关闭构建；更新Docker打包所需模块、示例配置、README及忽略规则。
- 人工确认8082原账号可登录及Cookie已入库；真实115写操作不作为自动回归测试。
- 按数据库与认证、115凭证、SHA1缓存功能划分提交；不自动推送或发布。
