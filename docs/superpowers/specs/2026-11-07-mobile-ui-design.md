# FileButler 移动端 UI 适配设计

状态：待用户审阅；布局方向已通过交互示意确认，本文不是实施完成记录。

## 目标与已确认方向

让手机用户能自然地浏览和管理本地文件及 115 网盘，不依赖双击、鼠标右键、悬停或跨窗口拖放。桌面完整模式和精简双栏模式保持原有交互。

用户已确认：

- 手机采用单栏、全屏页面式布局；底部提供文件、窗口、任务入口。
- 普通浏览使用单击打开、行尾更多菜单；多选模式显示复选框和底部批量操作栏。
- 操作菜单从底部展开，沿用已有动作和分组。
- PowerRename 使用规则和预览两个标签页；原名、新名上下排列，执行按钮固定底部。
- SuperRename 使用文件夹分组、吸顶标题和单组执行按钮；允许多选与启用深层目录。
- 共用现有业务逻辑，不建立一套独立移动端文件操作 API。

此前两版 HTML 为可交互示意，不是可直接投入生产的组件。示例文件、任务数量、编号和模拟完成行为不定义业务规则。

## 本次范围与非目标

首版范围覆盖登录、初始化、本地根目录、115 账号选择、文件浏览与常用操作、预览和文本编辑、详细信息、复制移动预览和目标选择、离线下载及解压、任务面板、PowerRename 和 SuperRename。

不新增后端文件能力，不改变权限、覆盖保护、跨账号限制、SHA1、编号算法、SSE 或后台任务生命周期。不增加原生 App、PWA 离线运行、手机跨窗口拖放或新的主题系统。不混入尚未提交的离线下载 200ms 刷新改动。

## 展示模式与状态

以下为设计者建议，随本文供用户确认：

- 可用视口宽度低于 768px 使用移动布局；宽度更大时保留现有桌面/精简模式偏好。窄屏布局不覆盖用户保存的桌面偏好。
- 宽度用于布局判断，指针能力用于触屏手势判断，不以设备 UA 决定。平板横屏仍可使用现有布局；窄屏电脑也可使用移动布局。
- 转屏和跨断点切换不丢失目录、账号、选择、滚动位置、剪贴板、编辑草稿和正在运行的任务；不重新提交操作。
- 手机只显示一个活动工作页面。窗口切换显示所有保留的浏览或工具会话，可切换或关闭；关闭有未保存文本的会话沿用原有确认逻辑。
- 本地与 115 的会话保持各自身份，不因为移动壳层切换而重建账号、重复登录或取消后台任务。

## 基础文件浏览

顶部显示标题与选择入口，下面是返回、上移、刷新以及根目录/账号切换。前进保留在导航更多菜单内，不能删除现有历史能力。路径栏展示当前路径，点击进入可编辑路径界面，复用已有解析逻辑。

文件列表以名称为第一行，大小、日期等辅助信息为第二行；文件夹、视频等类型保留图标。完整字段通过详细信息查看，排序通过菜单选择，不靠横向滚动表格实现。

正常模式单击文件名打开目录或支持的预览；不支持预览的文件不擅自下载或解压，压缩包遵循现有解压入口规则。行尾更多仅操作对应项，不意外改变其他已选项目。

进入多选后，点击行或复选框切换选择，不打开文件；全选、取消和选择数量明确可见。底部导航换成复制、剪切、删除、更多。复制或剪切后恢复导航，显示可访问的待粘贴提示；切换目标目录后可粘贴、取消剪贴板或查看来源。真实操作仍经过原有预览和确认。

菜单分组由共享动作定义驱动，不为手机复制一份权限判断。文件夹空白区域的操作由顶部更多入口提供。115 不展示不支持的源连接点动作，压缩包识别和禁用条件沿用已有实现。

## 弹窗、预览与任务

重命名、新建文件夹等短表单使用适配窄屏的弹窗；离线链接、解压选项等较长表单允许内部滚动。复杂操作预览、目标目录选择、媒体预览、文本编辑和详细信息采用全屏页面。

表单沿用统一灰色底部按钮区。目标目录在手机上单击进入；路径编辑、上移及输出文件夹规则保持现有语义。长错误信息可换行，不能被底部按钮遮住。

任务入口集中展示后台进度，单任务详情可以打开独立页面，但不在手机叠加可拖动窗口。取消和后台运行含义不变：返回或后台运行只是离开详情，任务继续；完成后关闭对应进度展示，不打断用户已切换到的其他页面。

应用内返回和浏览器返回优先退出最上层菜单/表单/工具页面，再返回目录历史；未保存编辑仍需确认。不用循环写历史的方式困住浏览器，不拦截退出整个应用的正常行为。

## PowerRename

作为工作会话全屏打开。规则页纵向排列现有匹配、替换、应用范围和选项；手机键盘弹出时输入框和执行区保持可达。

切换规则/预览不清空输入、滚动或预览状态。修改规则使旧预览失效，只有与当前输入一致且满足原有执行条件的预览才能提交；沿用既有取消过时请求和防重复提交逻辑。

预览将原名、新名上下展示，长名称换行，错误和冲突就近展示。仅看变化等筛选只控制展示，不改变待执行集合。工具保留现有功能范围，不因示意省略某个选项而删掉功能。115 的修改文件属性仍禁用。

底部固定取消和执行按钮，展示实际待执行数量。不能用示意中的固定编号或固定 12 项代替现有计算结果。

## SuperRename

每个目录是一组，组标题在列表滚动容器内吸顶，包含展开、组选择、目录名、重命名按钮。长目录名可截断并通过可点击的详情查看完整路径，不依赖悬停；执行按钮不被挤出视口。

组内展示原名及完整目标相对路径，例如 `视频/V01.mp4`。选择、编号宽度、V 前缀、视频目标文件夹等完全复用当前规则。取消选择只使相应目录重新计算，不能重排其他目录。复选框不因取消勾选而变灰。

未匹配文件和目录采用明显警告色并说明原因。更深目录默认不匹配，用户启用后按独立目录组处理；折叠只改变展示，不改变选择。父子目录选择范围沿用现有逻辑，不能把同一文件重复加入任务。

单组执行仅锁定该组，防止重复提交。确认后台任务成功后移除完成组；失败保留并显示错误，部分失败不能把未成功项目当作完成丢掉。其他组的展开、选择和滚动保持稳定。

底部提供批量执行入口，只执行当前有效选择；组级与批量执行需要共享进行中状态，禁止重复提交同一项。大列表复用已有按需渲染策略，避免为了固定标题或按钮同时挂载多份完整预览。

## 复用与组件边界

沿用 React/TypeScript 和现有 UI 样式体系，不引入新的移动 UI 框架。

- 文件会话、选择、导航历史、剪贴板、任务订阅和操作控制保持共享。
- 新增移动端壳层，负责单页展示、窗口切换、返回层级和底部导航。
- `FilePane` / `FileRow` 的数据和动作保持共享，可拆出桌面表格与手机列表展示组件。
- `ActionToolbar` 和菜单共享动作模型，移动端只改变呈现方式。
- `WindowFrame` 的坐标、拖动、缩放逻辑只用于桌面；手机不靠强制最小宽度或缩放整页适配。
- PowerRename / SuperRename 抽出可复用内容及状态控制，壳层决定弹窗、桌面窗口或手机全屏页面。
- 逐步拆分 `FileWorkspace` 的展示职责，避免复制整个文件或继续集中堆叠设备条件。

## 触屏与可访问性

主要点击区域建议至少 44px，复选框可见尺寸可以较小，但行点击应提供足够热区。竖向滑动优先滚动；手机文件行不启动桌面拖动传感器，不用 `touch-action: none` 锁死列表。

保留现有 `100dvh` 基础并处理安全区、软键盘及可用视口变化。菜单与弹窗管理焦点，关闭后回到原触发位置；所有图标有可读标签，不能只靠颜色表达失败/禁止。列表和工具中的滚动不带动整个页面横向溢出。

## 验收标准

1. 360px、390px、430px 手机宽度以及横屏可正常操作；桌面完整模式和精简双栏无回归。
2. 本地与 115 均能完成浏览、切换位置、多选、复制剪切粘贴、重命名、删除、详细信息和各自支持的预览/解压操作。
3. 键盘展开时输入、错误及确认按钮可见可达；关闭弹窗后焦点与滚动位置合理恢复。
4. PowerRename 切换标签保留状态，过时预览不能执行；请求错误原样可读且不自动重复提交。
5. SuperRename 组标题与执行按钮可达，取消勾选仅本组重排，深层目录启用可用，失败组不消失。
6. 窗口切换、转屏、离开进度页面或关闭浏览器不取消已提交后台任务。
7. 用组件测试和移动视口端到端测试验证交互；实际手机检查滚动、键盘和返回行为。测试只能使用临时样例，不能删除或重命名真实 115 数据。
